# 账号与云存档经验

> v3.4.56 加固（docs/20261124-1120-v3.4.56-持续集成与账号服务加固-GLM-5.4.md）

## 产品边界

- **账号是可选项，不是启动门槛**：不登录必须能完整游玩；账号服务挂了只能让账号面板显示未连接，不能影响 localStorage 存档、离线缓存、剧情推进。
- **云存档整包同步最省心**：`Saves.exportData()` 已是完整备份格式，直接上传整包，复用 `importData` 的校验/回滚/引擎回标题；不要为云同步重写逐槽位迁移。
- **上传前剥离瞬态字段**：删除 `currentSession`、`incompleteKeys`，否则会把某台设备的当前画面写进云端。
- **冲突绝不静默覆盖**：`revision` + `baseRevision`，不匹配返回 409，让玩家二选一；自动同步冲突后暂停。

## 后端

- 密码/找回码只存 scrypt 哈希；会话只存 token 哈希；`ctx.user` 可带哈希材料供校验，但 `userPublic()` 必须白名单输出。
- SQLite 用 WAL + 外键级联；删除账号靠 `ON DELETE CASCADE` 清 sessions/saves。
- 所有动态 SQL 用预编译语句；不要拼 `JSON.stringify(id)` 进 SQL（会生成双引号标识符）。
- 账号服务只依赖 Node 内置模块（`node:sqlite`），迁移时复制 `server/` + 数据目录即可；Node 24 会打印 SQLite 实验警告，属正常。
- **版本号不要缓存**：`VERSION` 在账号服务目录根部，而部署脚本只在 `server/` 有变化时才重启容器。
  若在模块加载时读一次，纯版本号发版后 `/api/health` 会一直报旧版本，线上核对会误判成「服务没更新」。
  正确做法是健康检查每次请求读一次小文件（v3.4.58）。

## 前端状态机

- 设置页挂载账号面板，不新增独立登录页；`AccountUI.mount()` 要防重复绑定（`dataset.acctBound`）。
- `boot()` 的 `/me` 是异步的：注册/登录会递增 `authRev`，boot 返回时必须比对启动时的代号，否则旧 `me=null` 会把刚显示的找回码页覆盖成登录页。
- 注册成功先展示一次性找回码专用页，再进账号面板；`render()` 不能只看 `state.me`，还要看 `state.view === "registered"`。
- 云恢复后 `Saves.importData` 会触发引擎 `backToTitle()` 并关闭设置浮层；不要在恢复后继续假设 `#cfg-account` 还在 DOM 里。
- 自动同步在 `sakura:saved` 后防抖 5 秒；导入期间用 `_importing` 抑制事件，避免半成品上传。
- **账号功能由部署决定（v3.4.55）**：`index.html` 的 `<meta name="gayme-account-api" content="off">` 是仓库默认值，
  关闭时不发任何请求、设置页不显示账号区块。带账号服务的部署在部署期改成空串（盒子由部署脚本执行
  `tools/patch_account_flag.py on`；`server/index.mjs` 自带接口时在内存里改写）。不要再写成「无论有没有后端都先探测一下」。
- **排定动作要看调用时的状态**：`busy` 为真时 `scheduleAutoUpload()` 会在开头直接返回，流程中途排的上传等于没排。

## 部署/代理（InstaBox 盒子）

- 站点根 `/data/home/sakura` 必须 `--exclude server`；账号代码放 `/data/home/gayme-account/app`，绝不能进公开目录。
- 账号容器：`node:24-bookworm-slim`，挂载 app 只读 + data 读写，发布端口只绑 `172.17.0.1:8096`；nginx 反代到该地址。
- **nginx 必须透传原始 `X-Forwarded-Host` / `X-Forwarded-Proto`**：InstaBox 前置代理会把 Host 改成 `127.0.0.1`，若 nginx 用 `$scheme` 覆盖协议，同源 Origin 校验必失败（403 csrf_blocked）。
- 部署后 `chmod -R a+rX`：Write 生成的文件常是 600，nginx worker 读不到会 403。
- 账号服务静态白名单要包含根 `sw.js`，否则 SW 注册 404；`/api/` 在 SW 中必须直接走网络。
- 部署脚本要同时处理：站点同步（排除 server）、账号 app 同步、容器重启、nginx 配置幂等补丁。

## 测试

- API 测试用随机端口 + 临时 SQLite，避免污染正式库；覆盖 409 冲突、force 覆盖、改密踢设备、找回码重置、5 次锁定、9MB 413、注销清云档。
- 浏览器 e2e 必须用真实 Node 服务，不要 mock fetch；至少覆盖注册→找回码→上传→换浏览器上下文登录→云恢复。
- 公网部署后再用 Playwright 跑一遍真实 URL，能抓到代理头、Secure Cookie、文件权限、SW 缓存这些本地测试抓不到的问题。

## 云存档上线前必须堵的四个坑（2026-11-24 实测，v3.4.54 全部命中，**v3.4.55 已全部堵上**）

回归用例：`tests/browser/cloud-guards.e2e.mjs`（`npm run test:cloud`，7 项；真实账号服务 + 临时数据库，不碰线上）。
服务端对应的用例在 `server/test_api.mjs`（31 项）。下面每条后面是 v3.4.55 的做法。

1. **空存档覆盖有内容的云端**：新设备登录后只勾「自动同步」、或清空本地后重新开局，都会把空状态
   推上云端并销毁原存档。上传前必须比较本机与云端的有效内容量；服务端也要拒绝"空覆盖非空"
   （旧版页面收到 409 会走已有的冲突界面）。云端必须留历史版本——没有历史的覆盖等于删除。
   **v3.4.55**：服务端两道保护 `empty_overwrite` / `progress_shrink`（进度量口径见 `server/progress.mjs`）；
   前端勾选自动同步时当场比较并暂停；设置页「清空」后自动同步暂停；云端历史版本每账号 10 版（`save_versions` 表）。
2. **共用设备串号**：退出登录不清本地存档、不重置自动同步开关；换账号登录时新账号云端为空就不触发
   冲突检测，下一次存档把上一个人的存档传进新账号。要给本地存档记归属，归属不符时禁止自动上传。
   **v3.4.55**：`localStorage` 的 `gayme_local_owner` 记归属；归属不符时自动同步保持关闭，由玩家在
   「上传到当前账号」与「留在本机」之间选择；退出登录可选一并清除本机存档。
3. **自动同步静默失效**：每次存档写入排一次"5 秒后上传"，正常阅读每句都会触发；按网络地址 15 分钟
   30 次的限流必然撞上，而自动同步只处理"冲突"一种错误，其余全吞。失败必须可见；限流按账号计；
   页面转后台要用带 keepalive 的请求立即上传（后台定时器会被浏览器冻结，关页时根本不执行）。
   **v3.4.55**：失败一律显示（冲突与保护 → 暂停让玩家选；限流 → 提示并按秒数重排；登录过期 → 提示）；
   只有存档真的变化才上传（待同步标记 + 变化代数 `dirtyGen`），两次至少间隔 60 秒；
   `visibilitychange` / `pagehide` 时带 `keepalive` 立即补传（监听要等引擎注册之后再挂，用 `DOMContentLoaded` 延后）。
4. **限流按网络地址计数**：校园网、公司网络下所有玩家共用一个桶（上传、注册、登录都是）。
   已登录的操作按账号计，地址维度只做防滥用上限。

其它实测结论：

- 转发地址请求头：网页服务器用"追加"方式转发，服务端取第一项；当前 InstaBox 边缘代理是"覆盖"
  行为所以取到的是真实地址，换成"追加"型代理就变成限流绕过。只信反向代理写入的那个值。（**仍未做**）
- `refreshAfterAuth()` 末尾排定自动上传的调用永远不生效：调用时 `state.busy` 为真，被
  `scheduleAutoUpload()` 开头的判断提前返回。排定动作要放在流程收尾之后。
- 账号模块在设置页首次打开时探测 `/api/health`：没有账号后端的部署（静态托管、安装包、测试环境）
  会多一次 404，把引擎端到端回归打红。（v3.4.55 已解决：账号功能由部署决定，见「前端状态机」。）
- 同步的密码哈希（`scryptSync`）会阻塞整个服务，一次登录校验约 190 毫秒。用异步版本。（v3.4.56 已改。）
- 新增涉及用户数据的功能，验证清单必须包含对抗性用例（空数据、换账号、限流、断网）与全量矩阵；
  v3.4.53 只验证了静态契约、账号接口和账号浏览器测试，回归红了几天没人发现。
- 账号服务放在免费沙箱上：空闲 30 分钟自动暂停、数据库零备份。接待真实用户之前必须有异地备份
  与常驻主机。（v3.4.55 已有本机每日备份、部署前备份、校验、演练与告警；**异地备份仍未做**。）

## v3.4.55 修复过程中新增的认识

- **「上传进行中又有新存档」的竞态**：上传成功后清「待同步」标记，会把上传期间新产生的变化一起丢掉。
  办法是记变化代数——上传前记下当时的代数，成功后只有代数没变才清标记。
- **两道保护要服务端和前端各做一份**：服务端那份对所有客户端生效（包括没刷新页面的旧版页面）；
  前端那份负责把 409 翻译成玩家听得懂的说明并提供选择。两边的「进度量」必须同口径，
  键名改动时静态契约会拦（`tests/static.test.mjs`「云存档进度量键名」）。
- **迁移回填要传对层级**：回填 `progress` 列时把整个存档包传给了进度量函数（应传 `payload.records`），
  回填出来全是 0。是「v3.4.54 老库自动迁移」那条接口用例抓到的——带数据的老库迁移必须有用例。
- **备份校验有盲点**：SQLite 自带的 `integrity_check` 对「文件尾部被截断」仍报正常。要另外核对
  「文件长度 = 头部页数 × 页大小」，并且真的把备份恢复到临时容器里跑一遍。
- **自动同步失败必须可见**，但暂停自动同步的时机要克制：只有「需要玩家做选择」的错误才暂停
  （冲突、两道保护）；限流、网络错误只提示并重试，否则玩家会被频繁的暂停打断。
- **历史版本恢复到本机后要暂停自动同步**，否则刚恢复的旧版本会被下一次自动上传再传回去。

## v3.4.56 账号服务加固的经验

- **慢哈希必须用异步版本**：`crypto.scryptSync` 占住事件循环，一次校验期间所有人的请求都排队。
  怎么测「不阻塞」：不要断言耗时（受机器快慢影响），断言**先后顺序**——发起登录校验，几毫秒后发健康检查，
  健康检查必须先返回。把计算改回同步，这条用例立刻变红。
- **哈希改异步后，模块加载时不能顺便算哈希**：「用户不存在时垫时间」的那次假哈希要改成第一次用到时再算并记住结果。
- **兼容性要专门测**：算法与参数没变不等于旧哈希一定能验——单元测试里用同步函数造一份「旧哈希」来验证。
- **客户端地址取转发头的最后一项**：`X-Forwarded-For` 的每一跳由经过的代理依次追加，只有最近一跳可信代理写入的
  那一项可信。前提是反向代理**原样透传**（nginx 用 `$http_x_forwarded_for`，不要用 `$proxy_add_x_forwarded_for`）。
  上线顺序：nginx 先于服务端是安全的，反过来会把所有玩家当成代理的地址。
  顺带把 IPv4 映射地址还原成普通写法，否则同一个玩家经不同入口会被算成两个地址、各占一份限流额度。
- **致命错误处理要保证「退出码是 1」**：先把 `process.exitCode` 置为 1，再挂一个不阻止事件循环排空的定时器去强制退出。
  只挂定时器的话，事件循环可能先排空、进程以 0「正常结束」，容器的重启策略不会把它当成崩溃。
  处理器单独成模块，在子进程里验证真的会退出。
- **文件权限要分三层**：进程掩码（管以后新建的文件）、启动时收紧已有文件、备份时收紧旧备份。只收紧不放宽。
  变异检查发现「进程掩码」这一层没有任何行为用例会变红——启动时的收紧已经覆盖了数据库文件，
  掩码是为将来运行期间新建的文件兜底，这一层改用静态契约守护。不是每层修复都能有行为用例，要如实说明。
- **审计记录的归属**：审计表的 `user_id` 没有外键（账号删除后历史记录可以保留）。指向已不存在账号的记录没有价值，
  定期清理顺带清掉；没有账号的记录（用户名不存在时的登录失败）必须保留。
- **测试里造「旧文件」要小心按日期清理的策略**：验证备份权限时造了一份文件名日期为 2026-01-01 的「旧备份」，
  被保留策略当成 30 天前的备份删掉了，校验时文件已不存在。造旧文件用「一小时前」这种不会被清理的时间。
- **新写的用例在本机也要单独跑一遍**：上面那条用例当时只跟着静态测试跑、没有被单独执行，到盒子上才暴露。
