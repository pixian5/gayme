# 账号与云存档经验

> 来源：v3.4.53 账号系统落地（docs/20261120-1321-v3.4.53-账号与云存档-Doubao.md）
> 最后更新：2026-11-20

## 产品边界

- **账号是可选项，不是启动门槛**：不登录必须能完整游玩；账号服务挂了只能让账号面板显示未连接，不能影响 localStorage 存档、离线缓存、剧情推进。
- **云存档整包同步最省心**：`Saves.exportData()` 已是完整备份格式，直接上传整包，复用 `importData` 的校验/回滚/引擎回标题；不要为云同步重写逐槽位迁移。
- **上传前剥离瞬态字段**：删除 `currentSession`、`incompleteKeys`，否则会把某台设备的当前画面写进云端。
- **冲突绝不静默覆盖**：`revision` + `baseRevision`，不匹配返回 409，让玩家二选一；自动同步冲突后暂停。

## 后端

- 密码/找回码只存 scrypt 哈希；会话只存 token 哈希；`ctx.user` 可带哈希材料供校验，但 `userPublic()` 必须白名单输出。
- SQLite 用 WAL + 外键级联；删除账号靠 `ON DELETE CASCADE` 清 sessions/saves。
- 所有动态 SQL 用预编译语句；不要拼 `JSON.stringify(id)` 进 SQL（会生成双引号标识符）。
- 账号服务只依赖 Node 内置模块（`node:sqlite`），迁移时复制 `server/` + 数据目录即可；Node 24 会打印 SQLite 实验警告，属正常。

## 前端状态机

- 设置页挂载账号面板，不新增独立登录页；`AccountUI.mount()` 要防重复绑定（`dataset.acctBound`）。
- `boot()` 的 `/me` 是异步的：注册/登录会递增 `authRev`，boot 返回时必须比对启动时的代号，否则旧 `me=null` 会把刚显示的找回码页覆盖成登录页。
- 注册成功先展示一次性找回码专用页，再进账号面板；`render()` 不能只看 `state.me`，还要看 `state.view === "registered"`。
- 云恢复后 `Saves.importData` 会触发引擎 `backToTitle()` 并关闭设置浮层；不要在恢复后继续假设 `#cfg-account` 还在 DOM 里。
- 自动同步在 `sakura:saved` 后防抖 5 秒；导入期间用 `_importing` 抑制事件，避免半成品上传。

## 部署/代理（InstaBox 盒子）

- 站点根 `/data/home/sakura` 必须 `--exclude server`；账号代码放 `/data/home/gayme-account/app`，绝不能进公开目录。
- 账号容器：`node:24-bookworm-slim`，挂载 app 只读 + data 读写，发布端口只绑 `172.17.0.1:8096`；nginx 反代到该地址。
- **nginx 必须透传原始 `X-Forwarded-Host` / `X-Forwarded-Proto`**：InstaBox 前置代理会把 Host 改成 `127.0.0.1`，若 nginx 用 `$scheme` 覆盖协议，同源 Origin 校验必失败（403 csrf_blocked）。
- 部署后 `chmod -R a+rX`：Write 生成的文件常是 600，nginx worker 读不到会 403。
- 账号服务静态白名单要包含根 `sw.js`，否则 SW 注册 404；`/api/` 在 SW 中必须直接走网络。
- 部署脚本要同时处理：站点同步（排除 server）、账号 app 同步、容器重启、nginx 配置幂等补丁。

## 测试

- API 测试用随机端口 + 临时 SQLite，避免污染正式库；覆盖 409 冲突、force 覆盖、改密踢设备、找回码重置、5 次锁定、9MB 413、注销清云档。
- 浏览器 e2e 必须用真实 Node 服务，不要 mock fetch；至少覆盖注册→找回码→上传→换浏览器上下文登录→云恢复。
- 公网部署后再用 Playwright 跑一遍真实 URL，能抓到代理头、Secure Cookie、文件权限、SW 缓存这些本地测试抓不到的问题。
