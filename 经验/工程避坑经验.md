# 工程避坑经验

> 来源：多轮开发实测踩坑整理（docs 里对应记录见文档索引）
> 最后更新：2026-10-24

## 批量修改源码脚本

- **行号区间漂移**：先收集全部行号区间再批量替换时，插入使文件变长会导致后续区间错位、静默失败。
  修复：每处理完一个节点**重新收集行号区间** + 替换结果**断言**（未命中即报错退出）。
  教训：曾有 39 节点脚本只写入 4 个且 2 个可能错位（幸未提交）。
- 批量插入脚本（tools/add_loops.py 等）要可重入：失败先恢复原文件再重跑。

## Unicode 码位

- **码位要查证，别凭印象**：⋯ 是 U+22EF（横省略号）不是 22EE（竖省略号）；
  〖〗 是 U+3016/3017 不是 3010/3011。写错会让字体覆盖检查放行错误字符。

## 浏览器/测试

- **顶层 const 不进 window**：脚本（script.js 的 SCRIPT 等）用全局词法绑定，
  e2e/控制台直接引用即可，`window.SCRIPT` 是 undefined。
- **defer 破坏正则**：`<script src` 精确匹配的正则在脚本加 defer 后失配，
  要用 `<script[^>]*src=`（属性顺序无关）。
- e2e 端口固定 41790，曾被占用报 EADDRINUSE：`lsof -ti tcp:41790 | xargs kill -9`。
- playwright 浏览器内核：本机只装 chromium（约几百 MB），没流量就别装 firefox；
  远端 CI 的 chromium 下载发生在 runner 上，不耗本机流量（已不再使用 GitHub CI）。
- **playwright 内核版本要对齐本地包**：`npx playwright install` 可能解析到 npm 缓存里的其它
  playwright 版本、装上不匹配的内核（本地包要 1248 却装了 1234，e2e 报 "Executable doesn't exist"）；
  用 `node node_modules/playwright/cli.js install chromium` 按本地包版本安装。

## 配置读取与无障碍（前端引擎）

- **读取不存在的配置键是静默陷阱**：`Saves.settings.sfx` 根本不存在 → `undefined === false`
  恒假，音效总开关形同虚设却不报错。配置项要有白名单契约，engine 只允许引用 DEFAULT_SETTINGS 已有键。
- **设置 UI 与默认值要对称**：`bgmVolume` 有默认值与合法范围却长期没有对应滑杆（只有音效音量）；
  新增设置项时同时补默认值、校验范围、设置面板控件。
- **高频更新的 `aria-live` 区要 `aria-busy`**：打字机每几十毫秒改一次 `textContent`，会让屏幕
  阅读器逐字播报；打字开始置 `aria-busy="true"`、完成置 `"false"`，SR 等整句完成后一次性朗读。
- **浮层识别靠 class 约定**：交互锁与通用清理都以「class 以 `-layer` 结尾」为准，只设 id 的浮层
  （如早期的 `perspective-layer`）会逃过判断，导致按键误推进剧情；新增浮层必须带规范 class。

## 数据契约与契约测试

- **同一功能的两套实现要同步**：inbox 回信与 free letter 回信是两份独立逻辑，
  v3.3.0 只修了 free letter 的 memory 取值，inbox 的同类 bug 又活了两个版本。
  复制粘贴出来的分支是高危区——改一处要全局搜同类实现。
- **契约测试正则要覆盖数据的全部写法**：memory 有对象 `{ id }` 和字符串 `"id"` 两种写法，
  旧测试只匹配对象格式 → 字符串里的重复 id 逃检了两个版本。写数据校验前先穷举形态；
  用 `(?<![_\w])` 规避 `requires_memory` 这类含目标词的前缀字段误匹配。
- **字符串取属性返回 undefined 不报错**：`"x".id` 合法返回 undefined，配合 `|| fallback`
  会静默用错值（inbox 曾把 memory id 写成 `brave`）。凡「可能是字符串也可能是对象」的字段，
  先 `typeof` 判断再取值。
- **收集类系统补「可达性」断言**：CG / 结局 / 记忆每条都要有解锁点，否则死条目永远收集不全。

## 交互机制设计（限时 / 焦点 / 快进）

- **限时机制存「起点时间」而非「剩余量」**：只存剩余或不落盘，反复开关会重置计时；应持久化
  首次打开时间戳，用 `deadline - (now - start)` 推算，天然防重置（inbox 倒计时曾可无限续命）。
- **浮层无障碍要配焦点陷阱**：`aria-modal="true"` 只是语义，Tab 实际仍会跑到背景；需在浮层内
  拦截 Tab / Shift+Tab 做循环，并在关闭时归还焦点。
- **自动连跳要设安全边界**：快进「跳过已读」必须排除一切有互动/副作用的节点（选项/信件/小游戏/
  视角/梦境/回声），并以「已读（visited>1）」为闸门，否则会跳过未读剧情或互动。

## 重构与迁移收尾

- **迁移后清理宿主侧重复文档**：玩法迁到 `js/games/*.js` 时常连带把 `node.xxx = {…}` schema 注释
  也搬了过去，宿主 engine.js 里的旧副本就成了重复死重（v3.3.6 清了 66 块 / 904 行）；
  跨文件迁移的收尾要检查源文件是否残留被搬走内容的副本。

## 字体覆盖

- 检查：`python3 tools/check_font_coverage.py`（需 .venv/bin/python + fonttools）
- **v3.2.4 起缺字已清零**（91 汉字 → 0），重建 `bash tools/rebuild_font_subset.sh` 需 WiFi（约 23MB 下载）
- 符号回退区放行 ≠ 全部字符覆盖：FALLBACK_RANGES 只管符号，汉字要真实在字体 cmap 里
- css 字体 URL 与 sw.js PRECACHE 里的 `?v=3.2.4` 是**字体版本**（随字体文件变），与 App 版本号解耦，不随 bump 更新

## 服务器部署

- 自动部署脚本放 `/usr/local/bin`（仓库外），放仓库内会被 git pull 覆盖
- cron 用 root 跑，避免 /opt 写权限与 git "dubious ownership"
- 首次 clone 后 HEAD=origin/main，要额外判断"从未部署过"才执行首次部署（/var/run/sakura-last-deploy 标记）

## 其他

- ssh 批量命令若输出为空：多半是引号嵌套被本地 shell 吃掉，改写成脚本文件 scp 上去再执行
- 临时脚本用完即删，避免污染仓库（verify_*.tmp.mjs 等）
- **审计结论也会误判**：`backToTitle` 的 `stopBgm→setScene` 曾被记为 bug，实为「停游戏曲 → 起
  标题曲」的设计（初始加载无声是浏览器自动播放策略）。动手前先确认「意图」，别把正常设计改坏。
- **工作区可能落后/混乱**：开工前先 `git fetch` + 比对 `HEAD` 与 `origin/main`，必要时
  `git reset --hard origin/main` 恢复到干净的权威状态，避免在错误基线上开发。
