# 版本与文档规范经验

> 来源：AGENTS.md 工作流要求 + 多轮实践整理
> 最后更新：2026-11-20（补：多模型并行下的文档债与 README 漂移教训）

## 版本号规则

- 每轮修改源码 +0.0.1，满十进一（新项目从 0.0.0 起）；当前 3.4.x 线（v3.4.51）
- 一键同步：`python3 tools/bump_version.py <新版本>`
  - 同步对象：VERSION / package.json / package-lock.json（v3.3.4 起）/ index.html
    （?v= 与标题页）/ sw.js（sakura-v 缓存）/ js/engine.js（GAME_VERSION 常量）
  - `js/engine.js` 头注释的 changelog 需手工补一行（一致性测试会兜底校验）
  - **别的版本字段会漂移**：package-lock 曾静默停在 3.2.0、css/sw 的字体 `?v=` 停在 3.2.4
    （字体版本随字体文件走、与 App 版本解耦，故意不 bump）；新增版本字段时记得补进 bump 脚本
  - **多模型并行会撞版号**：远程可能已有别的模型推过同号版本，push 被拒时先 fetch，
    看清远程已做了什么，重叠部分复用、独有部分升号（本项即 v3.3.3 撞号后改 v3.3.4）
- **坑**：写死版本号会漂移（renderAbout 曾写死 v2.7.8 漂了两轮）；一律走常量 + bump 脚本

## 文档规范（AGENTS.md 要求）

- docs 命名：`年月日-时分-标题-模型名.md`（如 20261023-0015-xxx-Doubao.md）
- 每轮必写：`当前开发进度` 与 `下一步待实现` 两篇 docs，README 里指向它们
- README 维护：【当前开发进度】【下一步待实现】【文档索引】链接 + 版本约定
- 根目录 `文档索引.md` 逐篇介绍 docs 里的每个文档（文档多了要及时补）
- **根目录 `经验/` 文件夹**：把 docs 分类整理成简洁经验（部署/规范/避坑/内容），docs 不一定都对，以实测为准

## 流程纪律

- 修改完必须检查正确再停止（全量测试绿 + 浏览器实测），严禁不检查就停
- 中文 commit，push 双远程（gitee + github）
- 不必要文件及时进 .gitignore（本轮无新增临时文件入库）
- 中文回复，专有名词英文后附中文；代码加中文注释

## 文档债教训（2026-11-20 复盘）

- 四天推进 8 个版本（v3.4.44~51）只有 1 篇追加记录：`docs/` 出现「版本有、文档无」的真空。
  补救成本高（需按 commit 正文倒推补档）。**每版至少一篇记录，或按批次合并并当天落档。**
- README 的「当前版本」行曾停在 v3.4.32（实际 3.4.51）、测试项数写 54（实跑 56）、
  【下一步待实现】里的 loopText 缺口早已收官、「同步 gitee 才部署」也随 gitee 移除失效。
  **发版脚本/契约只校验 VERSION 五处一致，不校验 README 正文——README 必须人工复核。**
- 建议每次发版后跑一次「三查」：版本行 / 测试计数 / 部署链路表述，与代码现状逐条对照。
