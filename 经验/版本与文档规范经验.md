# 版本与文档规范经验

> 来源：AGENTS.md 工作流要求 + 多轮实践整理
> 最后更新：2026-10-23

## 版本号规则

- 每轮修改源码 +0.0.1，满十进一（新项目从 0.0.0 起）；当前 3.2.x 线
- 一键同步：`python3 tools/bump_version.py <新版本>`
  - 同步对象：VERSION / package.json / index.html（?v= 与标题页）/ sw.js / js/engine.js（GAME_VERSION 常量）
  - `js/engine.js` 头注释的 changelog 需手工补一行（一致性测试会兜底校验）
- **坑**：写死版本号会漂移（renderAbout 曾写死 v2.7.8 漂了两轮）；一律走常量 + bump 脚本

## 文档规范（AGENTS.md 要求）

- docs 命名：`年月日-时分-标题-模型名.md`（如 20261023-0015-xxx-Doubao.md）
- 每轮必写：`当前开发进度` 与 `下一步待实现` 两篇 docs，README 里指向它们
- README 维护：【当前开发进度】【下一步待实现】【文档索引】链接 + 版本约定
- 根目录 `文档索引.md` 逐篇介绍 docs 里的每个文档（文档多了要及时补）
- **根目录 `经验/` 文件夹**：把 docs 分类整理成简洁经验（部署/规范/避坑/内容），docs 不一定都对，以实测为准

## 流程纪律

- 修改完必须检查正确再停止（全量测试绿 + 浏览器实测），严禁不检查就停
- 中文 commit，push 双远程（gitee + github）
- 不必要文件及时进 .gitignore（本轮无新增临时文件入库）
- 中文回复，专有名词英文后附中文；代码加中文注释
