# v3.4.62：部署失败也告警（拉取 / 备份 / 健康检查）

- 日期：2026-11-28 21:40
- 版本：v3.4.61 → v3.4.62
- 范围：`tools/box_cron_deploy.sh`、`tools/test_box_cron_deploy.sh`；无玩法与剧情改动

## 问题

v3.4.60 只给「部署成功后公网自检失败」加了 Bark 告警。部署流程里真正会挡住发版的几处仍然只写日志：

| 失败点 | 原行为 | 后果 |
|---|---|---|
| `git fetch` 失败 | 写一行日志，退出 | 盒子可能连续几小时不更新，没人知道 |
| 部署前数据库备份失败 | 写日志，不部署，下次重试 | 一直重试一直失败，只有翻日志才发现 |
| 健康检查失败 → 回滚 | 写日志、记 `failed.sha` | 新版本被回滚，用户看到旧版，没人被通知 |
| 部署脚本自更新失败 | 写一行日志 | 盒子长期跑旧脚本，后续修复不生效 |

## 方案

新增 `alert_once(key, title, body)`：去重标记放 `$STATE_DIR/alert-<key>`，同一故障只推一次；标题统一「樱时信笺·部署告警」，正文继续用 `python3 json.dumps` 序列化（v3.4.61 的教训）。

接入四处：

- **拉取失败**：key `fetch`。成功后 `rm -f alert-fetch`，下次再断能再推一次；故障期间每 3 分钟重试不会刷屏。
- **备份失败**：key `backup-<commit>`，正文带提交短 sha 与「修好后下次运行会重试」。
- **健康检查失败回滚**：key `rollback-<commit>`，正文带版本、提交、失败原因、回滚目标，并说明该提交不再自动重试。
- **脚本自更新失败**：key `selfupdate-<commit>`，正文说明盒子仍在用旧脚本。

`notify()` 从「固定标题 + 一个正文参数」改成「标题 + 正文两个参数」；公网自检仍用「樱时信笺·发版自检」。

## 权衡

- 没有给「账号容器重启失败」单独加告警：重启失败通常会在紧随其后的健康检查里暴露，再由回滚告警统一推送，避免同一件事推两条。
- 没有给「同步被中断」单独加告警：健康检查的 `site_in_sync` 会判失败并回滚，同样由回滚告警覆盖；回滚后仍不一致只写日志并留 `incomplete`，因为此时已经推过一条，且之后每次运行都会静默重试。
- 去重标记不主动清理（除 `fetch`）：失败提交由 `failed.sha` 挡住不会重跑，标记数量随发版增长但每个只是几字节，可忽略。

## 回滚

只改两个 shell 脚本，`git revert` 即可；旧版的问题是部署失败静默，不建议回滚。
