# v2.9.8 · 自动存档：本地进度自动记忆，防刷新丢失

> 时间：2026-10-11 09:08
> 版本：v2.9.7 → v2.9.8
> 需求：刷新网页 / 关闭页面后进度丢失——增加本地进度自动记忆，标题页一键恢复。

## 一、机制

| 环节 | 设计 |
|---|---|
| 写入时机 | `gotoNode` 推进到新节点即静默写入（读档恢复 `restoring` 路径不写，避免无谓覆写） |
| 节流 | 3 秒内多次推进只落一次盘（连续快进不放大写盘量） |
| 兜底 | `pagehide`（刷新 / 关页）与 `visibilitychange → hidden`（切后台/最小化）时**绕过节流强制落盘**——刷新前的最后位置必然被记录 |
| 存储 | 新键 `sakura_letters_autosave_v2`，payload = `{ savedAt, snapshot }`（snapshot 与手动存档同构） |
| 恢复 | 标题页「继续游戏」在**自动存档与快存槽（S 键）之间取时间戳更新的一份**恢复 |
| 生命周期 | `AUTOSAVE_KEY` 并入 `GAME_STORAGE_KEYS`——导出 JSON / 导入 / 清空所有数据 自动覆盖，无需单独维护 |

## 二、改动清单

- `js/saves.js`：`AUTOSAVE_KEY` 定义并入 `GAME_STORAGE_KEYS`；新增
  `autoSave(snapshot)`（缺 nodeId 拒绝写入）/ `getAutoSnapshot()`（损坏数据安全回退 null）/
  `clearAutoSave()`。
- `js/engine.js`：`autoSave(force)` 节流包装（3s）；gotoNode 非恢复路径末尾调用；
  pagehide / visibilitychange 强制落盘监听；「继续游戏」改为双候选取新。
- `tests/storage.test.mjs`：新增「自动存档写入、读取与清空覆盖」——
  非法载荷拒绝、损坏 JSON 回退、clearAll 覆盖、导出/导入往返含自动存档。

## 三、验证

- `npm test`：**32 / 32** 全过（新增 1 项）。
- 浏览器端到端实测：新游戏 → 推进到 `d4_puzzle` → **真实刷新页面** → 点「继续游戏」→
  恢复到 `d4_puzzle`，日程条显示「第 4 日 · 傍晚」，0 控制台错误。
- 节流实测：3 秒内连跳两个节点只落最后一次盘；pagehide 触发后键值立即更新为当前节点。

## 四、行为说明

- 刷新后回标题页，需要**点一次「继续游戏」**——不做过激的自动强拉（避免玩家想重开时被打断）；
- 中途刷新落在玩法节点上时，恢复后重玩该玩法（判定以玩法完成时写入的记录为准，无副作用）；
- 自动存档只记「最后位置」，不替代 9 槽位手动存档（重要分支前仍建议手动存）。
