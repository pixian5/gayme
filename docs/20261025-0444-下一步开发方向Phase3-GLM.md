## 2. P0 · 快跑债务止血（建议 v3.3.18 ~ v3.3.21，各半天内）

### P0-1 GitHub Pages 失同步处理（v3.3.18）
- **问题**：Pages 永久停在 v3.2.2，但 pixian5.github.io/gayme 链接仍对外可达——拿到旧链接的人玩到的是落后 30 个版本的旧版，且没有任何提示。
- **方案（二选一，不引入 CI）**：
  - A（推荐）：建 `gh-pages` 孤儿分支，只放一个重定向页 `index.html`（`<meta http-equiv="refresh" content="0;url=https://oh.sbbz.tech:8080/">` + 文字链接），
    仓库设置 Pages 源切到该分支——旧链接自动跳到唯一正式源，零维护；
  - B：仓库设置直接关闭 Pages。
- **验收**：curl pixian5.github.io/gayme 返回重定向页 / 404；README 删除 Pages 试玩链接，仅保留 oh.sbbz.tech。

### P0-2 PWA 首装体积分层（v3.3.19）
- **问题**：SW `install` 阶段 `addAll` 49 项（含 8MB BGM + 2.5MB CG），手机流量下首次打开即下载 11MB，且任一文件失败整个预缓存失败。
- **方案**：三层策略
  - 核心层（install 预缓存）：html/css/js/字体/图标/manifest ≈ 1.3MB——离线必需；
  - 媒体层（运行时缓存）：`audio/*.ogg`、`assets/cg/*` 首次请求时写入缓存（cache-first），不阻塞安装；
  - 版本换仓时媒体层缓存**沿用**（文件名含内容哈希或按 URL 保留），避免每次发版重下 10MB。
- **验收**：首装 SW 预缓存 ≤ 1.5MB；断网时已听过的 BGM / 已看过的 CG 可用；e2e 加「install 后 cache 条目数」断言。

### P0-3 本地质量门禁自动化（v3.3.20）
- **问题**：无 CI 后，「忘跑测试直接 push → 3 分钟后坏版本自动上线」没有任何拦截。
- **方案**：纯 git 原生 pre-push 钩子（`.githooks/pre-push` + `git config core.hooksPath .githooks`，零依赖）
  跑 `npm test` + `test:syntax` + `git diff --check`；e2e 因耗时默认不跑，`PREPUSH_E2E=1` 时启用。
  `tools/setup-hooks.sh` 一键启用（新机器 clone 后执行一次）。
- **验收**：故意引入语法错误 push 被拦；正常 push 通过 < 5 秒。

### P0-4 服务器部署回滚能力（v3.3.21，服务器侧）
- **问题**：cron 脚本只会前进，坏版本上线后只能等下次 push 修复。
- **方案**：部署脚本改为「rsync 到 `/var/www/sakura.next` → 健康检查（curl 200 + 版本串匹配 + 关键 JS 可加载）→ 原子切换 symlink → 旧目录保留为 `.prev`」；
  失败自动保持旧版并写日志；提供 `sakura-rollback.sh` 一键回退。
- **验收**：模拟 VERSION 与页面不一致 → 不切换；手动回滚后线上恢复旧版本号。

### P0-5 bump 工具闭环（并入 v3.3.20）
- `tools/bump_version.py` 增加校验：engine.js 头注释是否含新版本行（三个模型并行时漏写过）；
  缺失则打印模板提示（不自动写，避免误生成说明）。

## 8. 流程与门禁（不阻塞、不依赖 CI）

- 每版：改动 → `bump_version.py` → `npm test` + `test:syntax` + `test:e2e`（内容版可跳 e2e）+ `git diff --check` → 中文 commit → push 三远程 → 3 分钟后 curl 校验线上版本；
- P0-3 落地后 pre-push 自动兜底前三项；
- 文档：`docs/YYYYMMDD-HHMM-标题-模型名.md` + 文档索引 + README 两段同步；经验类沉淀进「经验/」4 篇对应文件而非新开；
- 多模型并行约定：接手前 `git pull` + 读最新进度快照；版本号以 `VERSION` 为唯一真相，冲突时顺延编号（v3.3.4→v3.3.15 已有先例）。
