# v3.4.59：发版自检脚本（verify_release）

日期：2026-11-28 10:45 · 模型：Doubao

## 为什么做

v3.4.57 把站点升到 3.4.57 后，`/api/health` 还报 3.4.56；v3.4.58 才把账号服务的版本号改成实时读取。
两次问题都出在同一处：**发版后的核对靠人手工 curl 两条地址**，站点与账号、8090 与 2096、响应头与
缓存仓分散在四五个命令里，漏看一条就会把「没更新」当成「已更新」。

本轮把这套核对写成一条命令，任何一项不一致直接非零退出。

## 脚本做了什么

`tools/verify_release.sh`，默认核线上 8090；也可传网址核本机预览。

| 段 | 检查 | 失败示例 |
|---|---|---|
| 1 | `/VERSION` 返回 200 且等于仓库 `VERSION` | 站点仍是旧版本 |
| 2 | `/api/health` 合法 JSON、`ok=true`、`database=ok`、`version` 与本地一致 | v3.4.57 那种账号版本滞后 |
| 3 | 首页响应头有 `X-Frame-Options: SAMEORIGIN`、CSP 含 `frame-ancestors 'self'` | 防嵌入加固被部署覆盖 |
| 4 | `index.html` 带 `?v=<版本>`、账号开关 `content=""`、`sw.js` 缓存仓为 `sakura-v<版本>` | 缓存仓没换、账号接口地址漂移 |
| 5 | 七个敏感路径均 404：`/server/`、`/tests/`、`/tools/`、`/docs/`、`/经验/`、`/文档索引.md`、`/.github/` | 部署排除名单失效 |
| 6（可选） | `--with-box` 时经 `instabox exec` 核盒内 2096 的 200 与两个响应头 | 2096 配置回退 |

要点：

- **响应头解析先统一小写再取值**。线上 nginx 走 HTTP/2 时头名是小写，本地假站点常见大写；
  macOS 自带 awk 不支持 `IGNORECASE`，早先按大写写死的解析在假站点上会误报。比较用忽略大小写。
- **`--with-box` 需要 `INSTABOX_API_KEY`**；没装 CLI 或没 key 时报失败而不是静默跳过，避免误以为核过。
- 退出码：`0` 全过、`1` 有失败、`2` 参数错误。

## 离线测试

`tools/test_verify_release.sh` 起一个本地假站点，按模式制造六种情形：

1. 全部正常 → 退出 0
2. 站点 `/VERSION` 落后 → 退出 1，指出不一致
3. `/api/health` 版本落后（v3.4.57 的真实事故）→ 退出 1
4. 缺 XFO / CSP → 退出 1
5. `/tools/` 可访问 → 退出 1
6. 账号开关指向外部地址 → 退出 1

踩过一个坑：假站点若继承调用方的 stdout 管道，脚本结束后管道不关，上层会一直等 EOF，
表现为「测试卡死」。现在后台进程输出重定向到文件，并在退出时先杀进程再清目录。

## 接入与验证

- CI：`.github/workflows/test.yml` 的 server 任务加一步 `bash tools/test_verify_release.sh`（纯离线，不访问线上）。
- 本地：`npm test` 71/71、语法通过、账号接口 36/36、nginx 补丁 9 情形、部署脚本流程测试、发版自检 6 情形全过。
- 线上：`bash tools/verify_release.sh --with-box` 23 项全过（版本 3.4.58 时核过一次；3.4.59 部署后再核一次）。

## 本轮环境说明

执行到一半 Mac 端连接中断，改在云主机的仓库克隆上完成余下改动与测试并推送；两端以 Git 为准，
Mac 本地的同名改动不再单独提交。

## 回滚

脚本只读线上，不改任何配置。回滚只需 `git revert` 本提交并删掉 CI 里那一步；不影响部署与游戏。
