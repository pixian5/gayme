# v3.3.4 真实 BGM 落地（自托管免版权曲目）

> 记录时间：2026-10-24 15:17
> 版本：v3.3.4（开发测试版 · Demo）

## 一、为什么做

v2.9.7 起 BGM 由 Web Audio 程序生成（和弦垫 / 低音 / 五声音阶随机游走旋律）。它零素材、体积为零，
但听感是「电子长音」，与樱花校园、书信叙事的基调差距明显，也是玩家反馈里最常提到的短板。
本轮在 WiFi 环境把 5 个场景 mood 全部替换为真实曲目，程序化配乐降级为兜底。

## 三、实现方式

### 1. 播放与切换

`js/engine.js` 的 BGM 段改成「真实曲目 + 程序化兜底」双层：

- `BGM_TRACKS` 把 mood 映射到本地 Ogg；首次播放时才创建 `new Audio()`（`preload="none"`，避免首屏下载 8MB）
- `playBgmForScene(scene)` 保持原场景分类不变，mood 未变且仍在播放则直接返回
- 交叉淡入淡出：`fadeBgm(prev, next, target)` 用 `requestAnimationFrame` 在 1.2 秒内把新曲 0→`bgmVolume`（默认 0.4）、旧曲同步降到 0 后暂停并复位
- 循环：`audio.loop = true`（曲目本身为无缝循环制作）

### 2. 自动播放拦截

浏览器的 autoplay 策略可能拒绝 `play()`（`NotAllowedError`）。此时挂起 `bindBgmUnlock()`，
监听一次 `pointerdown` / `keydown` 后按当前 `state.currentBg` 重试，不打断游戏流程。

### 3. 兜底

任一曲目触发 `error`（文件缺失 / 解码失败）→ `bgmRealUnavailable = true`，
后续全部改走原 `playMelody(mood)` 程序化配乐；同一套 `stopBgm()` 负责停掉两条链路。
所以删掉 `audio/` 目录游戏仍能出声，只是回到旧听感。

### 4. 离线与部署

- `sw.js` 预缓存加入 5 首曲目，PWA 离线时 BGM 仍可播放（缓存版本随 `bump_version.py` 同步）
- 服务器为静态托管，无需额外配置；Ogg 为 Chromium / Firefox / Safari 17+ 原生支持

## 五、验证

- `npm test`：38 项全过；`npm run test:syntax` 通过
- `npm run test:e2e`：chromium 全流程通过（含 5 首曲目之外的 daily 解码断言、控制台零错误）
- 专项浏览器验证（临时脚本，未入库）：
  - 日常场景 `daily.ogg` 播放中（`currentTime` 递增、音量 0.40）
  - 切场景 400ms 时旧曲 0.27 / 新曲 0.13 交叉中，1.4s 后旧曲暂停且归零、新曲 0.40 循环
  - 设置面板关闭 BGM 后 5 个 audio 元素全部暂停
  - 全程无 pageerror / console error
- 修复过程中发现并修掉一个真实缺陷：`requestAnimationFrame` 时间戳可能早于 `performance.now()`，
  首帧 `k` 为负会把 `audio.volume` 设成负数并抛异常 → 已把 `k` 夹到 `[0,1]`

## 六、后续可做
