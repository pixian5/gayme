## 一、三个关键玩法的结果分流（5 个新叙事节点）

三个玩法的判定分支（thresholds / interpretations / recipes）本就携带 per-result 的 `next`，
但此前所有结果都指回同一节点——结果只影响面板文案。本版把不同结果的 `next` 指向新写的
结果叙事节点（纯 script.js 数据改动，零引擎改动）：

| 玩法 | 结果 | 新节点 | 叙事要点 |
|---|---|---|---|
| d15_flag 旗阵（第 15 日·诗雨） | perfect（选对） | `d15_flag_hit` | 「你的眼睛，比我想象的可靠」——被理解的呼应 |
| | miss（选错） | `d15_flag_miss` | 「循环这么多次，总有一次会选对的」——循环语气的温柔回避 |
| d4_puzzle 拼图（第 4 日夜·匿名信） | letter_named（拼出「樱信·夜名」） | `d4_puzzle_named` | 「为什么不敢写下自己的名字？」——推动次日当面询问 |
| d5_perfume 调香（第 5 日·苏念） | sakura_letter（调出「樱时信笺」） | `d5_perfume_sakura` | 第一瓶留证 + 「樱花祭那天再开封」——标题点题回收 |
| | 其余三个结果（夏墨/静暮/不成香） | `d5_perfume_other` | 木匣与手写标签——「气味是会跑的记忆」 |

其余结果（puzzle 的无名/夜樱/拼不成形）保持原有后续不变（即基线文本）。

## 二、关键词合成回忆（6 段）

- `js/script.js` 新增 `COMPOSED_MEMORIES`（6 个合成产物各一段，樱花信除外——它是真结局钥匙）；
- `js/engine.js` 合成按钮处理：`composeKeyword` 成功后查表，未解锁则 `saveMemory` +
  flashHint「✦ 合成回忆：标题」。

| 产物 | 回忆 |
|---|---|
| 祭信 | 樱花祭的回信——樱花落在信封上，像谁盖下的邮戳 |
| 未寄信 | 没贴邮票的信——收信人那一栏，她始终没敢写 |
| 挣紫 | 挣出来的紫——紫是憋在胸口的那口气 |

| 她的选择 | 并排的两张纸——她最后选的不是那条更稳的路 |
| 替她回 | 代笔的勇气——写给不敢回信的自己 |
