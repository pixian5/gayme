## 一、为什么换一套试玩方法

前几轮的验证都是「图走查（graph.e2e）」——直接调 `gotoNode` 遍历 441 个节点。
它能证明**节点不崩**，但证明不了**玩家能玩下去**：它绕过了对话框点击、选项点击、
玩法操作这些真人必经的路径。上一轮 20 分钟真机试玩就连挖出 3 个走查跑不出的 bug。

本轮改为「点击驱动」：模拟器只做真人会做的动作——点对话框推进、点选项、在玩法里
按说明操作、点确认按钮。只有走不下去才记录，不强推。

## 三、发现的真实问题（已修 1 个）

### 问题 1：PWA 注册抛错，连带丢失更新提示 ✅ 已修（v3.4.24）

**现象**：认真画像控制台抓到一条 `Cannot read properties of undefined (reading 'update')`。

**定位**：`index.html` 里

```js
const reg = await navigator.serviceWorker.register("sw.js");
setInterval(() => reg.update().catch(() => {}), 5 * 60 * 1000);   // reg 可能是 undefined
```

**为什么以前没被发现**：这条代码在 `addEventListener("load")` 里，而游戏交互早就开始了；
图走查只看 `pageerror` 是否影响节点渲染，这条不阻塞剧情，就被漏掉了。

**真实影响**：`register()` 返回 undefined 时（SW 被策略禁用、已有其他 scope 等情况），
这一行抛错会**中断后面的 `controllerchange` 监听注册**——玩家再也收不到
「✦ 新版本已就绪，刷新页面生效」的提示。等于 PWA 的更新通道对这部分用户静默失效。

**修复**：`if (reg && typeof reg.update === "function") { setInterval(...) }`。

### 问题 2：学姐线入口对普通结局玩家永久锁死 ⚠️ 待你拍板（设计问题，非 bug）

`day2_choice` 的「★ 旧校舍后面（？）★」要求 `state.playCount >= 1`，
而 `playCount` **只在真结局（`true_end`）时 +1**；普通结局只加 `loopCount`。

后果：一个玩家如果连续走三次好结局都没合成樱花信，`playCount` 永远是 0，
**永远看不到学姐线入口**，也永远打不出 SIDE 结局《看见》。

这可能是刻意设计（学姐是三周目奖励），但 README 里「学姐线」是明写的内容。
**三个选项**：
- A) 保持现状，但在关于页/流程图里注明「需真结局后解锁」（零成本，最诚实）
- B) 门槛改成 `playCount >= 1 || loopCount >= 2`（普通结局两次也能进，约 1 行）
- C) 门槛改成 `loopCount >= 1`（第一次普通结局后就能进，学姐内容更易被发现）

**我建议 B**——既不剥夺「多周目奖励」的意味，也不让走普通路线的玩家永久错过一整条线。

## 四、17 个「未走通」的玩法：逐个实证，全是模拟器手不够巧

认真画像报告了 25 条（去重后 17 个玩法）「12 秒真实互动未触发收尾」。
这些**不是游戏缺陷**，但也不能只靠猜——我用三个专项探针逐个验证了可解性：

| 玩法 | 门槛 | 实测 | 判定 |
|---|---|---|---|
| `d3_rubbing` 拓印 | 覆盖率 ≥ 50% | 之字扫一遍 → **61%**，按钮点亮，出结果 | ✓ 可通关 |
| `d4_tealeaf` 茶渍 | 覆盖率 ≥ 30% | 圆心螺旋扫一遍 → **34%**，按钮点亮 | ✓ 可通关 |
| `d4_shadow` 影子 | 重合度 ≥ 50% | 拖到 0.65 位置 → **67%** | ✓ 可通关 |
| `d5_piano` 钢琴 | 按揭示的序列点键 | 播放后序列会显示，按序点击即可 | ✓ 可通关（诊断器读错了琴键标签） |

**根因是我的模拟器**：它挑面积最大的元素当操作目标，结果选中了外层
`ru-stage` 容器而不是里面的 `<canvas>`——事件发给容器，画布的监听器收不到，
覆盖率永远是 0。真人点的是画布本身。（已修正模拟器：优先取 `canvas`。）

这也反过来证明了一件好事：**这些玩法的加载、渲染、监听、判定逻辑都没有坏**，
只是需要真人那样的精细手势。

## 五、值得保留的观察（不构成缺陷）

- **灰置按钮提示只覆盖确认类**：v3.4.21 的「还没完成交互——XX 目前不可用」只作用于
  `-confirm/-submit/-finish` 三类。而「开始」这类启动键按下后变灰是正常状态，
  不该提示——当前实现是对的，模拟器早期误报过，特此记录避免以后改错。
- **toggle 型卡片要防手抖**：气味辨认（`scentmem`）的卡片是点一次选中、再点取消。
  真玩家不会连点，但**快速双击会把选中的又取消**，确认按钮随之变灰。
  如果以后收到「点了没反应」的反馈，优先怀疑这里。
- **计时类玩法需要真实时长**：心跳 12 拍约 10 秒、接字 15 秒。任何自动化测试
  给的时间预算少于 8 秒都会假失败——这条已写进模拟器的注释。
