# v3.4.58 账号健康检查版本号实时读取（2026-11-28 09:44）

> 模型：Doubao · 基线 v3.4.57

## 一、发现经过

v3.4.57 部署后核对线上：

- 站点 `/VERSION` = 3.4.57；
- `/api/health` 仍返回 `"version":"3.4.56"`。

站点已更新、账号服务报旧版本，说明账号服务的版本号不是实时值。

## 二、根因

`server/api.mjs` 在**模块加载时**读一次 `SITE_ROOT/VERSION` 并缓存：

```js
const VERSION = (() => fs.readFileSync(path.join(SITE_ROOT, "VERSION"), "utf8").trim())();
```

盒子部署脚本只在 `server/` 目录有变化时才重启 `sakura-account`（重启会中断在途请求、清空限流计数，
所以平时不想重启）。v3.4.57 只改了 `tools/` 与文档，`VERSION` 虽然同步到了账号目录根部，
但容器没重启，进程里仍是启动时读到的 3.4.56。

影响：所有「只改前端/文档」的发版，`/api/health` 的版本号都会滞后，线上核对会误判成「服务没更新」。

## 三、修复

把版本号改成每次请求时读取：

```js
function gameVersion() {
  try { return fs.readFileSync(path.join(SITE_ROOT, "VERSION"), "utf8").trim(); }
  catch (_) { return "dev"; }
}
```

`/api/health` 改为 `version: gameVersion()`。健康检查一次只读一个小文件，代价可忽略；
以后纯版本号发版不用重启容器也能报对。
