## 一、选型：static SDK

HF Spaces 支持 Gradio / Docker / static。本项目是纯前端零构建静态站，
**static SDK 最合适**：不需要 Dockerfile、冷启动为零、文件直接由 CDN 提供。

- Space：https://huggingface.co/spaces/xbzsb/sakura-letters
- 直连游玩地址：https://xbzsb-sakura-letters.static.hf.space/index.html
- 关键：static Space 需要根目录 `README.md` 带 YAML frontmatter（`sdk: static`），
  项目根 README 没有 frontmatter，直接推会被判配置缺失 → 单独维护
  `tools/hf-space-readme.md`，部署时覆盖到 Space 的 README。

账号 `xbzsb` 原有 4 个 Space（xxsy-frontend / xxsy-backend / microsoft365-e5-renew / Whisper），
本轮新建 `sakura-letters`。

## 二、踩到的两个坑（务必记住）

### 1. HF 拒绝裸二进制推送（必须走 LFS / Xet）

首次推送直接失败：

```
Your push was rejected because it contains binary files.
Please use https://huggingface.co/docs/hub/xet to store binary files.
Offending files:
  - assets/cg/*.webp (11 张)
  - audio/bgm/*.ogg (5 首)
  - fonts/NotoSerifSC-{Regular,Bold}.woff2
  - icons/*.png
```

HF 模板仓库的 `.gitattributes` 只覆盖模型格式（safetensors/pt/zip 等），
不包含 webp / ogg / woff2 / png / svg，所以这些文件按普通 blob 推 → 被 pre-receive hook 拒绝。

解决：往 `.gitattributes` 追加 LFS 规则 + `git lfs install --local` + `git add --renormalize .`。
**注意**：如果二进制已经进了上一个 commit，光 renormalize 不够——被拒是因为**推送范围里**
仍存在裸 blob，必须把那个 commit 重写掉（本项目只有一个部署 commit，用
`git commit --amend` 即可；多个 commit 时需要 rebase 重写历史）。

### 2. 直连域名多一层 `.static`

`https://xbzsb-sakura-letters.hf.space` → 404（HF 官网 404 页）。
正确域名是 `https://xbzsb-sakura-letters.static.hf.space`。
定位方法：抓 Space 页面 HTML，搜索 `iframeSrc` / `embedSrc`，里面写着真实地址：

```bash
curl -s "https://huggingface.co/spaces/xbzsb/sakura-letters" | grep -o 'iframeSrc[^,]*'
# → iframeSrc":"https://xbzsb-sakura-letters.static.hf.space/index.html"
```

## 三、落地物

| 文件 | 作用 |
| --- | --- |
| `tools/deploy_hf.sh` | 一键同步：克隆/更新 Space 仓库 → rsync 运行文件 → 覆盖 README → 补 LFS 规则 → 提交推送 → 轮询线上版本校验 |
| `tools/hf-space-readme.md` | Space 首页文案（带 `sdk: static` frontmatter、直连地址、玩法简介） |

脚本只同步**运行所需文件**：`index.html` / `favicon.svg` / `manifest.webmanifest` / `sw.js` /
`VERSION` / `css` / `js` / `fonts` / `audio` / `assets` / `icons`，
不含 docs、经验、tests、tools、node_modules —— Space 体积 12MB（其中 LFS 对象 10MB）。

token 一律走环境变量 `HF_TOKEN`，**不写进仓库**（仓库公开）。

## 五、使用方式

```bash
# 首次或每次发版后
export HF_TOKEN=hf_xxx            # write 权限；不要提交进仓库
bash tools/deploy_hf.sh

# 换目标空间
HF_SPACE=用户/空间名 bash tools/deploy_hf.sh
```

脚本末尾会轮询 `https://<user>-<space>.static.hf.space/index.html` 直到 200，
再比对 `/VERSION` 与本地一致才返回 0，避免「推送成功但其实没生效」。

## 六、注意与后续

- HF Space 是**镜像**，不是主源：GitHub 仍为唯一开发主线；改完记得同步三远程与服务器部署
- PWA 在 Space 的 iframe 内（huggingface.co 页面）受第三方存储分区影响，`localStorage` 存档
  可能与直连访问不共享；建议直接给玩家直连 `.static.hf.space` 地址
- 若将来想自动化，可在服务器 cron 里追加一步 HF 同步，但需把 token 放到服务器环境变量，
  涉及密钥管理，本轮先保持手动，避免扩散凭据
- Space 也可作为 itch.io 之外的另一个分发入口（HF 无 zip 审核流程，更新即时生效）
