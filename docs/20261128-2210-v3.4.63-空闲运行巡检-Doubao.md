# v3.4.63：空闲运行巡检（站点 / 账号 / 证书）

- 日期：2026-11-28 22:10
- 版本：v3.4.62 → v3.4.63
- 范围：`tools/box_cron_deploy.sh`、`tools/test_box_cron_deploy.sh`；无玩法与剧情改动

## 问题

v3.4.60/62 的告警都只在**部署过程**里触发。部署成功之后，如果站点开始 5xx、账号容器退出、证书快到期，没有任何主动检查——只有玩家访问或人打开日志才会发现。盒子 cron 每 3 分钟本来就在跑，顺手做一次体检几乎不花成本。

## 方案

新增 `runtime_check()`，只在 `PREV = CUR`（没有新提交）时执行，检查三项：

| 检查 | 判定 | 跳过条件 |
|---|---|---|
| 8090 首页 | HTTP 必须 200 | 无 |
| 账号 `/api/health` | 必须含 `"database":"ok"` | 账号容器不存在 |
| 2096 TLS 证书 | 剩余天数 ≥ 14 | 连不上 2096 / 不是本机可解析的证书日期 |

状态变化才推送：

- 异常：按类型用 `alert_once`（`status-web` / `status-account` / `status-cert`），标题「樱时信笺·运行告警」，同一故障只推一次；
- 恢复：三个标记任意一个存在且本次全部正常 → 删除 `alert-status-*`，写「运行巡检恢复正常」，推「樱时信笺·运行恢复」。

`alert_once` 的返回值改为：真正推送返回 0，已推过返回 1。调用方据此只在**首次**故障时写日志，避免每 3 分钟往日志里刷同一行。

## 为什么不做自动重启

巡检只告警、不自动 `docker restart`：容器反复崩溃时自动重启会掩盖根因，还会把故障变成「每 3 分钟重启一次」的循环。部署流程本身已有健康检查与回滚，运行期的问题交给人判断。

## 误报控制

- 2096 连不上直接跳过证书项，没开 TLS 的部署不会天天报「证书异常」。
- 没有账号容器时跳过账号项。
- 只有状态从正常变异常才推；异常持续期间不重复推；恢复推一次后标记清空，再出问题会重新推。
- 巡检在部署进行中不跑（只在新提交处理前的那次空闲运行跑），避免把同步中的短暂不一致误判为故障。

## 测试补强

- 旧的「空闲运行不产生任何 curl」断言改成「不产生 restart / backup」——巡检本身就要 curl。
- 新增情形 11：
  1. 去掉首页 200 → 空闲运行退出码 0，日志出现「!! 运行巡检：站点 8090 无法访问（HTTP 500）」，Bark 收到「运行告警」；
  2. 站点仍挂再跑一次 → Bark 仍只有 1 次；
  3. 恢复首页 200 → 日志「运行巡检恢复正常」，Bark 收到「运行恢复」，`alert-status-web` 标记被清除。
