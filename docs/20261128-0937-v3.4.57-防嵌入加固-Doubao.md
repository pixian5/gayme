# v3.4.57 防嵌入加固（2026-11-28 09:37）

> 模型：Doubao · 基线 v3.4.56（`bbe9efe`）
> 范围：只改 nginx 配置补丁工具与离线测试，游戏本体无玩法、剧情、存档改动。

## 一、问题

线上 8090 与 2096 两个站点都没有防嵌入响应头，任何第三方页面都能用 `<iframe>` 把游戏套住，
再叠一层透明按钮骗点击（点击劫持）。

- 页面 `meta` 里的 CSP 管不了 `frame-ancestors`；
- `Cross-Origin-Opener-Policy` 管的是弹窗隔离，`Cross-Origin-Resource-Policy` 管的是资源被谁引用，都拦不住内嵌；
- 这两个头只能由 HTTP 响应发。`server/index.mjs` 已经给 Node 直接服务的页面发了 `X-Frame-Options`，
但生产环境的静态站由 nginx 提供，走不到 Node 那一层，所以缺口在 nginx。

## 二、拉取时发现的问题（v3.4.57 半成品）

工作区里有一份未提交的 `tools/patch_nginx_account.py`（+46 行，2026-11-24 15:07），想做这件事但没做完：

1. 调用未定义的 `changed_has()`，脚本直接 `NameError`，离线测试第一条就崩；
2. 测试仍按 v3.4.56 的预期写「2096 不引入 `security_headers.conf`」，而新逻辑往每个 `location` 都插 include，两边冲突；
3. 第三步注释写「配置没变、只补安全头文件」，代码却要求「配置有改动」才执行，纯升级场景永远不会补；

结论：这份改动不能提交、不能上线，本轮重写。

## 三、做法

### 3.1 每个站点各一份安全头文件

`security_headers.conf` 放在各自 `conf.d` 目录下（8090 与 2096 是两个独立挂载）：

```
add_header X-Frame-Options "SAMEORIGIN" always;
add_header Content-Security-Policy "frame-ancestors 'self'" always;
```

### 3.2 引入位置：server 级 + 每个 location

nginx 的 `add_header` 只在「当前层级没有写 add_header」时才继承上一级。只要某个 `location`
自己写了 `add_header`，server 级的就被整体丢弃。所以不能只写 server 级，必须在每个 `location`
各 `include` 一次；重复 include 不会产生重复响应头（location 自己的一组会覆盖继承）。

### 3.3 脚本流程

1. 两份配置先在内存里改完；任何一份认不出写法就一份都不写；
2. 补丁后的配置只要引用了 `security_headers.conf`，就保证该目录下有这个文件——
   **与配置是否变动无关**，兼容「v3.4.56 升上来、配置没变只缺文件」的场景；
3. 写配置前备份（`*.bak-hardening-<时间戳>`），改安全头文件前备份（`*.bak-frames-<时间戳>`）；
4. `nginx -t` 任一容器失败 → 恢复全部备份，新建的文件直接删除，不重载；
5. 全部通过才 `nginx -s reload`，只重载真正改过的容器。
