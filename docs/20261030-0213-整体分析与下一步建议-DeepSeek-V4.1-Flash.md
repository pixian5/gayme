## 三、本轮新发现（按优先级，全部有数据）

### 3.1 SW 首装重复下载约 1.2MB（P0，唯一的真性能问题）

**现象**：首访 2,341KB；二次访问 0KB。拆开资源时序后看到同一个文件被下载两次：

```
/js/script.js            (无 ?v=，来自 SW 预缓存安装) 413,392 B
/js/script.js?v=3.4.25   (页面实际加载)              413,392 B
/js/engine.js            124,766 B
/js/engine.js?v=3.4.25   124,766 B
```

**根因**：`index.html` 全部资源用 `?v=3.4.25`（14 个脚本 + 2 个 CSS），
而 `sw.js` 的 `PRECACHE` 用的是**裸路径**。SW 在 install 阶段按裸路径再抓一遍，
于是首装把整套 JS/CSS 下载两次（`PRECACHE` 26 项合计 2.06MB，其中应用代码约 1.36MB）。

**为什么必须修**：不只是流量——首装时 SW 安装与页面加载抢带宽/主线程，
弱网手机上是实打实的白屏时间；线上 gzip 后重复部分约 250–300KB，仍不可忽略。

**方案（v3.4.26，已实现）**：
- `sw.js`：`PRECACHE` 中 **js/ 与 css/ 条目改为与 index.html 完全相同的 `?v=<VERSION>`**；
  字体保持 `?v=3.2.4`（CSS 里就是 3.2.4，不能跟着版本号变）。
- `tools/bump_version.py`：新增一段只替换 `js/`、`css/` 开头条目的 `?v=`，避免手工漂移。
- `tests/static.test.mjs`：新增契约——index.html 每个带 `?v=` 的资源，必须在 PRECACHE 中以**完全相同 URL** 出现；同路径裸版本不得出现。
- `tests/browser/engine.e2e.mjs`：断言首次加载的资源条目里**不存在** `/js/*.js` 无 `?v=` 的请求。

**实施中发现的两个附带问题（已一并修复）**：
1. `index.html` 第 9–11 行还有 3 条**裸路径 preload**（saves/script/engine），同样造成重复请求；
2. `PRECACHE` 漏了 `js/ui/panels.js`（离线首装缺 UI 面板脚本，运行时缓存虽能兜底，但首装离线会缺）。

**实际验收（2026-10-30 02:35）**：首访请求 **25 → 19**；本地未压缩 transfer **2,341KB → 1,750KB（-25%）**；
裸 `/js/*.js` 请求 0 条；二次访问仍 0KB；DCL 242ms；契约 **47/47**、e2e/graph 全过。
（未达到最初 1.4MB 预估，是因为首装仍需把 16 个版本化文件装进 SW 缓存；剩余体积就是首装必需量。）

### 3.2 Firefox 从未真正跑过（P1）

`engine.e2e.mjs` / `graph.e2e.mjs` 都支持 `BROWSER=firefox`，但上一台机器下载 Firefox
46 分钟无进展后中止，此后一直只有 chromium 证据。本云环境网络正常，
`npx playwright install firefox` 约 90MB，应在本轮补齐——这是「双内核」宣称与实际证据的最后一处缺口。
若 Firefox 暴露 Web Audio / SW / CSS 差异，正好在发布前修掉。

### 3.3 移动端触控没有自动化回归（P1）

现状：`test:graph` 有 390×844 **视口**走查，但整个 `tests/browser/` 里
**没有任何 `hasTouch` / `isMobile` / `touchscreen` 用例**。玩法层有 22 处 pointer 事件，
实际手机上的多点、双击、拖动、长按从未被自动验证；设置面板/对话栏的
`safe-area-inset` 与 `100vh` 也只靠肉眼。

**方案（v3.4.27，已实现）**：新增 `tests/browser/mobile.e2e.mjs`（390×844、hasTouch、isMobile）：
1. 8 个代表玩法先挂载并校验「说明栏折叠（真触控点按）+ 跳过按钮在视口内且触控可收尾」；
2. 断言 `document.documentElement.scrollWidth <= clientWidth`（无横向溢出）；
3. 存档浮层触控开关、面板四边不越界、`#game` 高度等于视口（100dvh）；
4. 全程 0 console error。
（原计划「按说明做完整手势通关」改为「挂载/说明栏/跳过收尾」：完整手势属于 `test:play` 的职责，
移动端这层先保证触控事件链路与布局不回归。）

### 3.4 立绘位图 0/5（P1，素材 + 内部生图可行）

CG 11/11 已位图化，但 `PORTRAIT_BITMAPS` 仍是空集合，5 位角色立绘全部是内联 SVG。
管线（v3.4.0）已经就绪：webp 放进 `assets/portraits/` + 清单登记即上线。
既然本轮不用 HF，**可以改用会话内置的生图能力**：先出 1 张诗雨样张定风格，
确认后批量 5 张（1024×1536 → webp q80），同时把 `/assets/portraits/` 加进 SW 的媒体缓存路径
（现在只匹配 `/audio/` 与 `/assets/cg/`，不加会退回核心缓存并随版本清空）。

### 3.5 自动存档失败是静默的（P2）

`Saves.autoSave()` 写入失败只 `console.error`，引擎侧忽略返回值（手动存档有失败提示）。
当 localStorage 配额满（WebView 隐私模式、iOS 存储压力）时，玩家会以为进度已保存，
刷新后回到旧位置。建议：连续 2 次失败弹一次「自动存档不可用，请手动导出备份」提示，
并引导到设置面板的导出按钮（导出/导入本身已完整存在，见下节）。

### 3.6 分发物料仍缺（P2）

`tools/pack-itch.sh` 能出 10MB zip，但 itch 页面需要：封面 630×500、3–5 张 16:9 截图、
简介/标签/操作说明文案。另：`og:image` 是相对路径、缺 `og:url`，社媒分享卡片可能不显示图。
这些都能在会话内生成（Playwright 截图 + 生图封面），只差最后的上传动作（需你登录）。

### 3.7 文档陈旧数字（P3）

README 测试章节仍写「42 项」（实际 46）；「SW 预缓存 42 项」实际 26 项。
顺手修正，避免下一个接手模型再次误判基线。
