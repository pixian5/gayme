## 三、改动一：学姐线入口门槛（方案 B）

### 问题

`day2_choice` 的「★ 旧校舍后面（？）★」原门槛：

```js
requires: () => window.__game && window.__game.state && window.__game.state.playCount >= 1
```

`playCount` **只在真结局（`true_end`）时 +1**（`engine.js` 结局结算处），普通结局只把 `loopCount` +1。
于是一个连续走普通结局的玩家 `loopCount` 一直涨、`playCount` 永远是 0，**永远看不到学姐线入口**，
也永远拿不到 SIDE 结局《看见》——而 README 里学姐线是明写的内容。

### 方案 B（用户拍板）

```js
// 门槛 v3.4.25（方案 B）：真结局一次，或任意普通结局累计两次即可进入。
// 原为 playCount >= 1，而 playCount 只在真结局 +1 —— 走普通结局的玩家会永久锁死这条线。
requires: () =>
  window.__game &&
  window.__game.state &&
  (window.__game.state.playCount >= 1 || window.__game.state.loopCount >= 2),
```

语义：**真结局一次**（老玩家的既得路径不变）或**普通结局两次**（新兜底路径）。首周目、仅一次普通结局
都仍然看不到——保留「多周目奖励」的意味，这正是选 B 而不是 C 的理由。

> 为什么不是 A：A 只在说明页标注「需真结局解锁」，等于承认一条 24 节点的线对多数玩家不存在。
> 为什么不是 C：`loopCount >= 1` 让第一次普通结局后就能进，学姐线会变成三选一之外的常规选项，
> 稀缺感与「三年前我也站在你这个位置」的分量都会削弱。

### 契约（新增第 46 项）

`tests/story-graph.test.mjs` 新增「day2 学姐线入口门槛」用例，用假 `window.__game.state` 探针锁死四种组合：

| playCount | loopCount | 期望 |
|---|---|---|
| 0 | 0 | 不出现（首周目） |
| 0 | 1 | 不出现（仅一次普通结局） |
| 1 | 0 | 出现（真结局一次） |
| 0 | 2 | 出现（两次普通结局，本次新增的兜底路径） |

这样以后任何人改这行门槛，都会先被契约拦下。

## 四、改动二：五画像试玩器入库

### 为什么需要它

`graph.e2e` 直接 `gotoNode` 遍历 441 节点，证明的是**「节点不崩」**；它绕过了点对话框、点选项、
在玩法里操作这些真人必经路径。上一轮 20 分钟真机试玩就连挖出 3 个走查跑不出来的 bug。

`tests/browser/playtest.e2e.mjs` 只做真人会做的动作：点对话框推进、点选项、在玩法里按说明操作、
点确认按钮。走不下去就记录，不强推。

### 五个画像

| 画像 | 行为 | 验证的东西 |
|---|---|---|
| `lazy` | 每个玩法都点「跳过这个玩法」 | 跳过链路是否完整、会不会卡住 |
| `careful` | 展开说明栏 → 启动键 / 拖滑杆 / 画布之字扫 / 点卡片 → 点确认；实在不行兜底跳过 | 玩法是否真的可操作、说明是否够用 |
| `explore` | 同 careful，但先展开说明栏读一遍；选项优先走苏念线 | 分支切换 + 说明栏内容是否真的能照着做 |
| `fast` | 注入全节点已读 + 快进，**什么都不点** | 已读快通（v3.4.13）是否真的自动收尾 |
| `loop` | 注入全节点已读 + `loopCount=2`，玩法走跳过，选项优先学姐线入口 | 循环计数、既视感文本不炸；学姐线隐藏入口 e2e 覆盖 |

判定口径：**必须真的走到结局节点**（`SCRIPT[node].ending` + 结局画面出现）、**控制台 0 错误**、
**允许兜底跳过但计数**（兜底率高说明玩法手势难度或说明有问题，是观察指标而非失败）。

### 实现要点

- 自起本地静态服务（41792，与 41791/41790 错开），只用 localhost；进页面先
  `Saves.updateSetting("bgm", false)` + `sfxVolume: 0` 静音（用户定的规矩），`textSpeed` 拉到 5 加速。
- 每个画像**独立 browser context**：快通/二周目要注入「全节点已读」，不能污染其他画像。
- 每个循环先抓一份快照（结局？选项？浮层？对白？），再按优先级动作；**卡死检测**用
  「节点 + 浮层名 + 选项数 + 确认键数」的组合键，连续 11 步不变即判失败并打印最近 25 个节点。
- 玩法内操作靠**临时 `data-pt` 标记 + 真实鼠标事件**（不直接调内部函数）：滑杆从左 1/4 拖到 72%，
  画布七行之字扫（覆盖类玩法需要面积），卡片每个只点一次（toggle 型连点会取消选中）。
- 五个画像默认**并行**跑（各自 context 隔离），墙钟时间取决于最慢的一条；`SEQ=1` 可串行排查。

### 四个踩坑（都写进了脚本注释）

1. **`tutorial-layer` 不是玩法层**：新档首次必现新手引导，它同样以 `-layer` 结尾，被判成「玩法浮层」
   后脚本一直点「跳过」→ 原地 250 步不动。已在快照里列入 `NOT_GAME` 白名单，并单独处理
   （点「开始故事」）。**任何按 `-layer` 结尾判断浮层的代码都要排除它。**
2. **`echo-layer` 没有跳过键**：回声/气味闪回这类「选项型浮层」是真实选择，不是玩法。
   兜底逻辑改为：没有跳过键就点浮层里第一个按钮（真人也是这么做的）。懒人画像在回声节点也会做选择。
3. **测试输出被管道缓冲**：`npm run test:play | grep ...` 在 CI/后台会一直没输出，看起来像卡死。
   排查时直接重定向到文件再 `tail`。
4. **预设被 `newGame()` 清掉——覆盖是假的**（本轮最重的一条）：`newGame()` 重置 `skipMode` 与
   `variables`，但不碰 `visitedNodes` / `playCount` / `loopCount`（这三个读自 Saves flag，引擎初始化时
   快照）。第一版 setup 把「全节点已读 + 点 #btn-skip」放在 `newGame()` **之前**，开局全被清掉——
   快通画像实际是在「没开快进」状态下跑，一次自动收尾都没有，却依然到达结局、测试全绿。
   **测试通过 ≠ 覆盖成立**。修复：注入移到 newGame 之后；并加两条断言防回归——结局时
   `state.skipMode` 必须仍为 true、`fastAuto` 必须 > 0。修复后快通画像 34 次自动收尾 / 仅 2 次兜底。
   顺带：引擎内部导航走闭包 `gotoNode`，测试侧猴子补丁 `window.__game.gotoNode` 拦不住内部调用
   （节点轨迹导出为空即此因），已移除该无效补丁。
