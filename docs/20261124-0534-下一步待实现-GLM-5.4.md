## P1-1 持续集成加入浏览器回归（30 分钟）

- 现状：`.github/workflows/test.yml` 只跑 `npm test` 与 `npm run test:syntax`。
- 做法：安装 Chromium 后依次加 `npm run test:e2e`、`npm run test:settings`、`npm run test:account`、`npm run test:account:e2e`、
  `npm run test:cloud`（后三套需要 Node ≥ 22 的内置 SQLite，流水线镜像要选对版本）。顺手把工作流注释里的旧项数改成实际数字。
- 验收：故意在 `js/account.js` 里制造一个未捕获异常并推一个分支，流水线必须变红。
- 注意：持续集成跑在 GitHub（镜像仓库）上；盒子从 GitCode 部署，不依赖流水线结果。

## P1-3 站点根改白名单同步（1 小时）

- 现状：部署脚本用「排除法」——把已知的非运行文件排除掉。v3.4.55 实测发现 `/scripts/check-meta.mjs` 与 `dist/itch/`
  下的上架截图此前公网可以下载（内容无害）。以后仓库根目录新增文件，仍可能被同步到公开目录。
- 做法：改为只同步运行文件（`index.html`、`sw.js`、`VERSION`、`js/`、`css/`、`fonts/`、`icons/`、`assets/`、`audio/`、
  `favicon.svg`、`manifest.webmanifest`、`robots.txt`、`sitemap.xml`、`NOTICE.md`、`PRIVACY.md`）；
  这份清单与 `server/index.mjs` 的静态白名单共用一个来源，静态契约保证两边一致。
- 验收：在仓库根放一个临时文件并部署，公网访问它是 404；离线流程测试加一条断言。

## P1-4 邮箱找回（1.5 天，需要你拍板）

现状：只有注册时显示一次的找回码。找回码丢了，账号和云端存档就永久取不回来。

做法：邮箱验证（注册时可选绑定）+ 邮件验证码或重置链接 + 频率限制。你已经有邮箱和发信授权码，可以自建。
先要你定两件事：是否强制绑定邮箱；是否同时提供找回码作为备用通道。

   监听器抛异常后，「没有 /api/ 请求」空洞地通过，直到另一个用例才暴露。
4. **部署脚本每改一次都跑离线流程测试**：`bash tools/test_box_cron_deploy.sh`，本机与盒子各跑一遍（两边的 rsync 实现不同）。
