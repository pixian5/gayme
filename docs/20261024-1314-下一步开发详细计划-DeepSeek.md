## 2. 方向 A：内容纵深（无需素材，可立即推进）

### P2-1　loopText 多周目文本扩散（目标 ≥120 节点）

策略：**高信号节点优先**、每次 3 段（初周 + 二周目既视感 + 三周目更深），遵循「不剧透 / 不解释循环 / 单调加深」。
按缺口分批（每批一版）：

| 批次 | 覆盖前缀 | 预计新增 | 重点节点示例 |
|---|---|---|---|
| Batch 1 | `senior_`（学姐线） | +12~15 | `senior_2`（初见）、`senior_7`（旧校舍）、`senior_10`（她的事）、`senior_13_*`（回信分支） |
| Batch 2 | `true_` / `true_break_`（真结局线） | +12~15 | `true_2`、`true_5`、`true_6`（樱花祭之夜）、`true_break_*` |
| Batch 3 | `afterword_`（后日谈） | +15~20 | `afterword_reply*`、`afterword_mailbox*`、`afterword_wall*`、`afterword_proofread*` |
| Batch 4 | 女主线 bad/normal + 共通线 | +20~25 | `sy_*_bad/normal`、`xz_*_bad/normal`、`sn_*_bad/normal`、`d2_/d3_/d4_` 关键节点 |
| Batch 5 | `prologue_` 剩余 | +8~12 | 序章未覆盖的情感节点 |

验收：`loopText` 结构契约（≥2 段、引号成对）通过；每批跑全量测试；抽检 3 个节点确认「加深不反转」。
改动文件：`js/script.js`（纯数据）。成本：中（创作量为主）。

### P2-2　信件回执 / 选择回响落地（需先定 UI）

现状：`Saves.saveLetter` 已写入「回信记录」，但 `getLetters` **无读取方**；经典选项 `choice.value` 尚无实现（v3.3.5 删了空块，字段保留）。

UI 方案（二选一，建议 A）：
- **A（推荐）历史面板「回响」标签**：`renderHistory` 顶部加 Tab「对话 / 回响」，回响列出玩家写过的回信内容（按节点 + 时间）。
- B 图鉴新增「回响」分类卡片。

实现要点：
- 新增读取 API：`Saves.getLetters()`（已有 recordStore 生成的 `getLetters`），或补充按时间排序的 `listLetters()`；
- 选项 `value` 接入：`showChoices` 里对带 `value` 的选项调用 `Saves.saveLetter(currentNodeId, opt.value)`（把回执真正落盘）；
- 引擎：`renderHistory` 改双 Tab；空态提示。
- 验收：选择后能在「回响」看到记录；e2e 断言选择→回响面板出现条目。成本：中。

### P2-3　结局 / CG 文案润色与「结局注释」

- 为每个结局补 1~2 句「回顾注释」（在结局图鉴卡片显示，帮助玩家理解分支）；
- CG 描述统一风格、错别字校对。
- 改动：`js/script.js`（ENDINGS/CGS 字段）、`engine.js renderGallery`。成本：低。

### P2-4　关键词 / 记忆审计

- 关键词 `KEYWORDS` 排序与稀有度分层（普通/稀有/隐藏）；
- 记忆去重、图鉴排序（按线路/时间）；`requires_memory` 全可达（已契约兜底）。
- 改动：`script.js` + `engine.js renderKeywords`。成本：低。

## 3. 方向 B：性能与加载（P1-6 结论）

现状场景全部为 **CSS 渐变 + 内联 SVG**，无位图，故「背景预取」价值极低。**建议下调/取消**，
改为两项低成本增强：
- **B1**：`<link rel="preload">` 预载字体子集与关键脚本（首屏更快）；成本：低。
- **B2**：场景切换时对 `#bg-layer`/立绘做「预合成」（预创建下一场景元素再切换）避免闪白；成本：低。
验收：e2e 首屏无控制台错误；人工抽检切换无闪。

## 4. 方向 C：素材管线与接入（引擎先行，需素材）

> 先把引擎做成「素材可插拔」，素材到位后「替换即上线」，当前程序化 BGM / SVG 为兜底。

### C1　音频素材管线（P3-1）
- 新增 `assets/audio/` 约定与清单；引擎支持按场景映射到音轨文件（mp3/ogg），
  加载失败或缺失时**回退现有程序化 BGM**；
- 淡入淡出、静音与音量沿用现有 `bgmGain/sfxGain`。
- 改动：`engine.js`（新 `playTrackForScene` + 回退）、`sw.js`（预缓存音频，可选）。成本：中。

### C2　位图资源管线（P3-2）
- 立绘/CG 支持 `png/webp`（webp 优先）、1x/2x；缺失时回退 SVG；
- 资源清单 `assets/art/…`；图鉴大图（v3.3.11 查看器）优先用位图。
- 改动：`engine.js`（立绘/CG 渲染层加「图片优先」分支 + 占位/失败回退）、`css`。成本：中。

### C3　素材接入与分发
- C3-1 真实 BGM 接入（需音频素材）；C3-2 AI 位图立绘/CG 接入（需图片素材）；
- C3-3 itch.io 打包分发：生成 zip（`index.html`+资产）、页面文案、封面图、版本号。成本：中。

## 8. 风险与回退

- **无素材**：程序化 BGM + SVG 立绘为兜底，C 方向不阻断主线开发。
- **工作区回退异常**：开工先 `git fetch` 比对 `HEAD`/`origin/main`，必要时 `git reset --hard origin/main`（本轮即遇到并已恢复）。
- **token 频繁失效**：AtomGit 与 GitCode 互为镜像，任一可用即不丢提交；本地测试为硬门槛。
- **改档风险**：开发测试版允许不兼容旧档，但改动前先导出（设置面板支持全量导出 JSON，v3.3.13 起支持单槽导出）。

## 9. 不可破坏的约束（继承）

1. 全量 `npm test` + `test:syntax` + `test:e2e` + `git diff --check` 通过才可停止
2. 叙事回溯仅保留 `d5_rewind`、`d15_rewind` 两处，且必须带 `timeLoop: true`
3. 真结局条件：三女主 GOOD 全通 → `true_unbroken`；合成樱花信并破环 → `true_end`；后日谈只由 `true_end` 解锁
4. 非回溯剧情边的日期与时段必须单调前进
5. 学姐不被召回樱海、不解释循环机制
6. 版本号每次 +0.0.1，满十进一
7. 每版完成：更新版本 → 跑全量测试 → 浏览器回归 → 写 docs → 中文 commit + push
8. 主项目 AtomGit（origin），GitCode 为备份 remote
