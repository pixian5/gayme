# 下一步开发方案（v2.7.9 → v2.8.7）

> 制定时间：2026-09-29 23:56
> 基准版本：v2.7.8
> 定位：从「堆玩法」转向「结构瘦身 + 内容纵深 + 表现升级」的执行路线
> 执行方式：每版一个工作单元，完成并通过验收后，由你决定是否继续下一版

---

## 一、现状诊断

| 维度 | 现状 | 判断 |
|---|---|---|
| 剧情 | 399 节点 / 约 2.3 万字，主线 + 3 女主×3 结局 + 真结局 + 后日谈全部打通 | 骨架完整，纵深不足 |
| 玩法 | 90 个交互玩法（v1.0~v2.7 每版 +4），占 engine.js 的 82%（14,773 行） | 数量过剩，同质化 |
| 存储 | 106 个 localStorage 键，每个玩法一组 get/set/clear 模板 | 膨胀，需抽象 |
| 工程 | 27 项测试全过；无 README、无 CI、版本号三处手工同步 | 基线尚可，缺自动化 |
| 表现 | BGM 为 Web Audio 随机音阶；立绘/CG 均为内联 SVG 字符画 | 明显短板 |

核心结论：**不再新增玩法**，把同样的投入转向「结构瘦身 + 内容纵深 + 音频/立绘」。

---

## 二、三条主线

- **A 结构瘦身**：玩法框架抽象（GameKit）→ 存量玩法分批外迁。不改行为，只改组织方式，每批都有测试兜底。
- **B 内容纵深**：补齐三处叙事缺口（沈屿家庭线 / 三女主旧交 / 学姐中段线索），并让关键玩法结果影响后续文本。
- **C 表现与发布**：音频 → 立绘/CG → 移动端/无障碍 → GitHub Pages 试玩发布。

## 三、版本路线

### v2.7.9 · 玩法框架基座（GameKit）
**目标**：建立统一玩法外壳，用最小批量验证，不动存量行为。

**改动清单**
1. 新增 `js/gamekit.js`（在 engine.js 之前加载）：
   - `GameKit.mount({ name, title, hint, onSkip })` → 返回 shell，统一创建浮层、提示条、跳过按钮、aria 标注
   - `shell.finish(score)`：统一收尾（写入 lastMinigameScore、跳转 next、移除浮层）
   - `shell.hint(msg)` / `shell.progress(n, total)` / `shell.timer(sec, onEnd)`
   - 自动注册 `window.GameLifecycle`（读档 / 返回标题时安全退出）
   - 统一键盘（Esc 跳过）与移动端触控偏移
2. 迁移 5 个后日谈玩法作为样板，移入 `js/games/afterword.js`：
   `runPostcard`、`runTimeline`、`runTriage`、`runWall`、`runProofread`
3. `index.html` 仅新增 2 个 script 标签

**验收**：`npm test` 全过 + `test:syntax` + `git diff --check`；浏览器逐玩法回归 5 项；旧存档兼容（脚本不涉及存储结构变化）。
**风险**：中低。迁移保持同名同签名，engine.js 只改调用点。

### v2.8.0 · 减重与一致性（里程碑）
**改动清单**
1. 迁移第二批 8 个结构简单的早期玩法，移入 `js/games/senses.js`：
   `runBreath`、`runTimecapsule`、`runFold`、`runReflection`、`runLightdraw`、`runMimic`、`runSeason`、`runPulse`
2. 新增 `tests/consistency.test.mjs`：校验 VERSION / index.html 三处 `?v=` / package.json 版本号一致
3. 清理死代码（如 `el.quickAccess` 指向不存在的 `#quick-access`，0 次使用）
4. 静态测试增加契约：新玩法必须经 GameKit 注册，防止回退

**验收**：同 v2.7.9 + 一致性测试通过。

### v2.8.1 · 内容纵深 A：沈屿家庭线 + 三女主旧交
**改动清单**

**验收**：剧情图测试（节点可达、时间线单调）+ 文本一致性 + 浏览器通读新节点。

### v2.8.2 · 内容纵深 B：学姐线索 + 长链呼吸点
**改动清单**
1. 第 10 日左右新增学姐「差点说漏嘴」节点，强化玩家对循环的怀疑
2. 第 6~15 日长链拆为 3 个小章节（第 6~8 日「旧物」/ 第 9~11 日「节奏」/ 第 12~15 日「归位」），每章开头加一段沈屿独白作为呼吸点

### v2.8.3 · 玩法结果影响叙事
**改动清单**

**改动清单**

## 五、不可破坏的约束（继承自 v2.7.7/v2.7.8 复核）

1. 全量 `npm test` + `npm run test:syntax` + `git diff --check` 通过才可停止
2. 叙事回溯仅保留 `d5_rewind`、`d15_rewind` 两处，且必须带 `timeLoop: true`
3. 真结局条件：三女主 GOOD 全通 → `true_unbroken`；合成樱花信并破环 → `true_end`；后日谈只由 `true_end` 解锁
4. 第 5 日路线必须由玩家明确选择，不按好感度静默抢占
5. 非回溯剧情边的日期与时段必须单调前进
6. 后日谈不新增惩罚结局；学姐不被召回樱海、不解释循环机制
7. 版本号每次 +0.0.1，满十进一（v2.7.9 之后为 v2.8.0）
8. 存档 schema 升级必须保留迁移或校验，导入失败按原始值回滚
9. 每版完成后：更新 VERSION / index.html / package.json → 跑测试 → 浏览器回归 → 写 docs 记录 → 中文 commit + push
