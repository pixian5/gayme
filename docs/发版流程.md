# 发版流程（两线共用规约）

> 2026-11-16 定稿 · 适用：本地线与云端并行线（WorkBuddy / 任意协作者）
> 根因背景：并行线 v3.4.37~39 只推了 GitCode，导致 GitHub/gitee 落后 4 提交、
> HF 落后 3 个版本无人发现。发版动作必须按下述顺序一次走完。

## 一、标准发版步骤（每次代码改动后）

```bash
# 1. 版本号（版本一致性契约会校验：VERSION/package.json/index.html ?v=/sw.js/engine 常量与头注释/changelog 首条）
python3 tools/bump_version.py 3.4.XX
#    然后手工补两处：js/engine.js 头部注释加一行 v3.4.XX 说明 + GAME_CHANGELOG 数组首条

# 2. 测试（在哪台机器跑都行；当前约定：InstaBox 盒子 /data/home/gayme-test）
npm test                # 54 项静态契约
npm run test:syntax     # 全 JS 语法
npm run test:defects    # 缺陷回归 11 项（输出末行会单列「跳过 N」）

# 3. 提交并推双远程（origin=GitHub 部署主源；gitcode=备份。2026-11-16 gitee 远端已彻底移除）
git add -A && git commit -m "v3.4.XX：<中文说明>"
git push origin main && git push gitcode main
#    pre-push 钩子会自动跑契约+语法+diff 检查，被拦截=测试挂了，先修再推

# 4. 部署：只部署 InstaBox 盒子（2026-11-16 用户指令）
#    推 origin 后盒子 cron 每 3 分钟自动从 GitHub 拉取——通常什么都不用做；
#    不想等时手动直推：bash tools/deploy_box.sh
#    HF Space 不再部署（保留在线上的 v3.4.43 作静态展示，不再更新）

# 5. 线上核对
curl -s https://8090-agqxoy6u363jxgfufg2onqxbm4.instabox.tech/VERSION   # 应等于本地 VERSION
```

## 二、盒子测试环境（InstaBox · box-c6119b）

- 位置：`/data/home/gayme-test`（克隆自 GitHub，Node 22 + npm ci + playwright chromium 已装）
- 每轮测试前：`cd /data/home/gayme-test && git fetch -q origin main && git reset -q --hard origin/main`
- 跑全套：`npm test && npm run test:syntax && npm run test:defects`
  （e2e 全家桶 `test:e2e / test:graph / test:mobile / test:play / test:overflow` 按需；
  首次跑浏览器用例前确认 `npx playwright install chromium` 已完成）
- 注意：盒子空闲 30 分钟自动暂停，`instabox exec box-c6119b -- '<cmd>'` 会自动唤醒

## 四、检查清单（复制用）

- [ ] bump 版本号 + engine 头注释 + changelog 首条
- [ ] npm test / test:syntax / test:defects 全过（跳过数已知）
- [ ] commit 中文说明，推 origin(GitHub) + gitcode 双远程
- [ ] 盒子 8090 版本核对（≤3 分钟 cron，或 deploy_box.sh 直推后立即核对）
- [ ] 不部署 HF（2026-11-16 起规约）
- [ ] docs/ 记录本轮改动 + 文档索引.md 加行 + README 进度段（两线都要，不许只写 commit message）
