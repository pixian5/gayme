# v2.9.0 · 修复 v2.8.7 迁移回归：引擎内部符号在 games 文件不可达

> 时间：2026-10-11 03:41
> 版本：v2.8.9 → v2.9.0
> 性质：bug 修复（第 3 / 4 批迁移引入的运行时回归，全部测试无法覆盖的类型）

## 一、问题

`js/games/*.js` 在 engine.js **之前**加载，IIFE 内只能访问全局（Saves / SCRIPT / GameKit），
engine.js IIFE 内部的 `applyAdd` / `updateHeartBar` / `gotoNode` / 辅助函数均不可达。
但自动化迁移与等价性校验都只对比「旧行是否保留」，未检查「新文件是否引用了不可达符号」，
导致三类问题漏网：

1. **tarot / dreamweave 直接 ReferenceError**：perception.js 调用了 engine 内部辅助函数
   `matchTarotCombo` / `matchDreamweave`——进入判定分支必崩。
2. **tarot / dreamweave / compass 效果块失效**：转换器的 record 捕获对多行 record 语句失效，
   `record + add/personality/memory` 整体留在了函数体内并原样调用 `applyAdd`——运行时崩溃，
   即使不崩，finish 属性也缺失（效果/记录双丢）。
3. 31 项测试全绿但以上问题都测不到（语法检查只查语法、注册契约只查字符串存在性）。

## 二、修复

1. `matchTarotCombo` / `matchDreamweave` 两个纯数据辅助函数从 engine.js 移入 perception.js
  （仅 tarot / dreamweave 使用）。
2. tarot / dreamweave / compass 三处改写为 canonical 形态：record / add / personality / memory
   全部进 `shell.finish({...})`，函数体内不再有引擎符号调用。执行顺序与迁移前一致
  （record → add → personality → memory → 结果面板）。

## 三、防线加固（tools/）

- `tools/migrate_games.py`：转换产物新增禁用标识符检查
 （applyAdd / updateHeartBar / gotoNode( / state. / setScene / renderCharacters / typewriter(），
  命中即列入 MANUAL 拒绝写入。
- `tools/equivalence_check.py`：对整个新 games 文件做禁用标识符扫描，先于逐行比对报告。

复扫结果：nature / perception / mechanism / imagery 四个文件 **0 处引擎内部符号引用**；
perception 仅余 3 条被删除的注释行（`// 应用效果` / `// 显示解读`），属预期差异。

## 四、验证

- `node --check` 全部 games 文件 + engine.js 通过。
- `npm test`：31 / 31 通过。
- 教训记录：**跨文件迁移类改动的验收必须包含「符号可达性」检查**，仅靠行级比对不够。
