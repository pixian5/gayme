# v3.4.13 · 已读快通（重玩体验 P0）

> 2026-10-26 · GLM · 依据：[20261026-0445-重玩体验分析与建议-GLM.md](20261026-0445-重玩体验分析与建议-GLM.md)

## 问题

快进的「跳过已读」（v3.3.6）不覆盖互动节点；89 个玩法仅 timecapsule 有跳过按钮；
而第 6~15 日玩法链（30+ 节点）每轮必经——多周目玩家被迫每轮手动重玩（单轮 ~40 分钟），
162 个 loopText 的前置体验堵点。

## 实现

| 层 | 改动 |
|---|---|
| `js/gamekit.js` | host 清单登记 `isFastReplay`（**关键坑：attachHost 只拷贝 host 已有键**，新能力必须先登记——本次调试实锤）；`createShell` 检测快进+已读 → 浮层顶部「⟲ 已读 · 快通中…（点击保留）」提示条，300ms 后 `cleanup + jumpNext`（中性收尾：无加成/不写记录/直达节点 next，复用生命周期清理链） |
| `js/engine.js` | attachHost 注入 `isFastReplay(nodeId) = skipMode && visited>1`；runMinigame 同条件直接按 50 分中性收尾（含 scoreJump 分支），不挂浮层 |
| `css/games.css` | `.fast-replay-bar` 提示条样式 |
| 交互设计 | 快进中**自动**完成（符合快进心智）；**点击提示条可保留这次玩法**（想重温的玩家不被剥夺）；choice/letter/echo 不受影响仍必停 |

## 验证

- e2e 新增快通断言（GameKit 玩法 + 基础 minigame 双路径）；首版断言踩了
  「下一节点也已读→链式快进」的选点坑，换未访问节点对（d7_firefly→windchime）后稳定；
- 全量：静态 42/42、e2e 全过、全图走查 441 节点 0 坏节点（快通默认不触发）。

## 效果

二周目重玩：30+ 玩法手动重玩 → 快进到底只在决策点停——**单轮 ~40 分钟 → ~10 分钟**。
多周目文本（loopText 162）从此真正可达。
