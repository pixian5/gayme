# v3.4.22 · 快进与视角节点解耦

> 2026-10-28 · GLM

## 问题

快进的「跳过已读」把 `perspective` 与 choice/letter/minigame 一并列为「互动节点」——
遇到带视角的节点会**停住等玩家手动推进，且没有任何提示**。
v3.4.20 把视角节点从 1 个扩到 13 个后，这个问题的影响面放大了 13 倍。

## 判断：视角是「可选补充」而非「必经互动」

- 视角内容是角色内心独白，**不看也不影响剧情推进**（不进记忆图鉴、不加好感、不写记录）；
- 与 choice（必须选）、letter（必须回）、minigame（必须玩）性质不同；
- 快进语义是「玩家不想停留」——在这种情况下还强制停下来，违背玩家意图。

## 修复

`isPlain` 判定移除 `!node.perspective` 条件：快进中已读的视角节点照常连跳。
👁 按钮依然在同一节点常驻（快进下约 80ms 窗口内可点），**想看可主动点，不想看就让它过去**。

## 验证（实机）

| 场景 | 结果 |
|---|---|
| 快进 + 已读视角节点（无门槛记忆） | d2_library_8 → d2_library_doodle 自动推进 ✓ |
| 快进 + 已读视角节点（有门槛记忆，👁 可见） | 120ms 时 👁 仍显示可点；不点则 80ms 后连跳 ✓ |

## 沉淀

`tutorial-layer`（新手引导）也是 `*-layer` 结尾，会阻断快进与自动化测试的“是否已推进”判定——
调试快进相关行为时须先关引导，否则会误判为「卡住」。
