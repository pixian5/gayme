# v3.3.21 · 服务器原子部署 + 一键回滚（P0-4）

> 2026-10-25 · GLM

## 问题

cron 部署脚本（v1）只会 rsync 覆盖 `/var/www/sakura`：预检缺失、无回滚——坏版本上线后只能等下次 push 修复。

## 方案（服务器侧，已安装生效）

| 组件 | 说明 |
|---|---|
| 发布目录 | `/var/www/releases/<sha>/`（保留最近 3 个） |
| nginx 根 | `/var/www/sakura` → **symlink** 指向当前版本（`ln -sfn` 原子切换） |
| 上一版 | `/var/www/sakura.prev` → symlink，部署时自动记录 |
| 部署流程 | 拉取（gitee 主/github 备，沿用 v1）→ rsync 到 `.staging` → **预检**（index.html 含 VERSION 串，失败保持旧版）→ 切换 → 健康检查（curl 版本串），**失败自动回滚**并记日志 |
| 回滚 | `sudo /usr/local/bin/sakura-rollback.sh`（prev/cur 互换，可来回切换） |
| 兼容 | 老实体目录首次运行自动迁移为 releases 布局；旧脚本备份 `sakura-deploy.sh.v1.bak` |

## 验证

- 安装后实跑：v1 cron 已部署同 commit → 新脚本按设计静默退出（无更新）；
- 脚本含「原子切换 / 健康检查自动回滚」路径确认在位（4 处标记）；
- 下一次 push 将实走完整链路（staging → 预检 → 切换 → prev 记录 → 健康检查），日志可查 `/var/log/sakura-deploy.log`。
