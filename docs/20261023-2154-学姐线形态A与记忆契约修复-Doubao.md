### 2. 修复既有 bug：free letter 回信 memory 对象格式

- 现象：4 组 free letter 回信分支（诗雨·敢/停/凌晨 ×3、夏织·教练 ×1）用**对象** `memory: {id, text}`，
  而 `Saves.saveMemory` 只认**字符串** id（严格 `===` 比较）→ 记忆永远无法解锁
- 修复：js/script.js 4 组改字符串 id；js/engine.js showLetter 加固（兼容字符串与对象旧数据）
- 影响面：无 requires_memory 引用这些 id，修复只让记忆正确入档，不破坏剧情解锁
- 契约：consistency.test.mjs 新增"free letter 回信分支 memory 必须为字符串 id"测试

## 三、经验与教训

1. **接口格式要统一并落契约**：saveMemory 只认字符串 id，但 4 组旧数据用了对象格式，
   静默失效（记忆永不解锁）——这次用一致性契约测试兜底，防止再犯。
2. **接手他人未提交工作前先只读验证**：先跑测试确认完整性与质量，再决定发布；不要贸然提交
   或覆盖。本轮验证 35/35 + e2e 7/7 后才 bump 发布。
3. **新结局类型可复用引擎默认分支**：SIDE 结局无需引擎特殊处理，走"普通结局循环+1"即符合
   "二周目内容"语义；避免为单一结局加类型分支。
4. **补录他人提交的 docs**：v3.2.4 提交未建独立 docs，本轮按提交信息补录，保持 docs 完整。
