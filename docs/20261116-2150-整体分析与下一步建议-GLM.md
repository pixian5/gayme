## 四、下一步开发建议（按优先级与成本排期）

### A. 立即收尾（合计约半天）

**A1 · 发版 checklist 固化**（半小时，流程）
把「bump 版本 → npm test → push 三远程 → deploy_hf → 盒子 cron 自动 → 线上版本核对」
写成 `docs/发版流程.md` 或并入 README，两端开发线共用；根因是并行线各自记流程导致
HF 漏发。可在 `.githooks/pre-push` 尾部加一行提醒「push 后记得 deploy_hf」。

**A2 · P9 塔罗逆位重叠**（10 分钟，攒到下个代码版本一起）
逆位标签绝对定位改 flex 布局或加 margin。

**A3 · 文档补账**（半小时）
v3.4.37~39 的修复要点并入 README 进度段（本文档已承接大半）。

### B. 用户拍板项（不拍板就不动）

| 项 | 说明 | 成本 |
|---|---|---|
| B1 · CF Origin Rule | 面板操作：Hostname in {oh,play}.sbbz.tech → Host Header 改写为 `xbzsb-sakura-letters.static.hf.space`。做完两域名立即复活 | 2 分钟 |
| B2 · itch.io 上架 | 素材全部就绪（封面/截图/文案/打包脚本 pack-itch.sh），只差注册账号上传。你此前说"先不管" | 半天 |
| B3 · 媒体离线缓存找回 | 现状：BGM/CG 离线不可用（SW 拦截媒体会触发 Firefox bug，v3.4.33 实验后放弃拦截）。候选方案：页面侧 Cache API + blob 手动管理，绕开 SW 拦截。离线体验加分项，非必需 | 中等（1~2 天） |
| B4 · i18n / 云存档 | 大工程，需求未明 | 大 |

### C. 内容与体验候选（自主可做，按价值排序）

**C1 · CG 图鉴缩略图**（1~2 小时）★推荐
图鉴卡片现在纯渐变+文字，但 11 张位图现成——`cgArt()` 已支持，卡片模板把
未解锁用占位、已解锁换缩略图即可。图鉴是视觉小说的核心回看入口，性价比高。

**C2 · 音效细节调优**（半天）
信件展开、回忆闪回两处选样可再挑；现有 8 采样覆盖主干交互。

**C3 · loopText 继续扩面**（每批半天）
443 节点中 177 处已有既视感文本（40%）。候选：d 链玩法节点的 prompt 短句
（v3.4.11 时明确搁置过的缺口）、三女主 good 链后段。

**C4 · 手势类玩法首次演示**（1 天，可选）
17 个涂抹/拖动类玩法说明齐全但纯文字。可给前 3 个高频玩法（拓印/茶渍/光影）
加一个 2 秒的"手指划过"示意动画。属打磨项，建议观察玩家反馈再定。

### D. 工程健康（低成本预防）

**D1 · GitHub Actions 纯测试 CI**（1 小时）★推荐
README 里挂过这项"需用户确认"。现在六套 e2e 全绿，正适合加一条只跑
`npm test + test:syntax` 的 workflow（不部署，部署仍走盒子 cron）——并行线合并前
就能在 PR 上看到契约是否破裂，避免再出现"合并时才发现另一条线改了什么"。
**是否加，等你一句话。**

**D2 · 盒子混部风险记录**（已有档）
盒子同时跑免流节点项目，删盒/迁移需先迁两边——已写入经验，维持。
