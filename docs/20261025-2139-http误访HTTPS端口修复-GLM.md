# 运维修复 · http:// 误访 HTTPS 端口（400 Bad Request）

> 2026-10-25 21:39 · GLM · 服务器侧配置修复（无代码改动）

## 问题

用户以 `http://`（浏览器输入 host:port 时的默认协议）访问 HTTPS-only 端口，
nginx 返回 `400 The plain HTTP request was sent to HTTPS port`。

## 修复：nginx 497 重定向（源站侧，已完成）

nginx 对「明文 HTTP 打到 SSL 端口」有专用状态码 **497**。在 sakura server 块加入：

```nginx
error_page 497 =301 https://$host:$server_port$request_uri;
```

效果：`http://oh.sbbz.tech:8080/` → 301 → `https://oh.sbbz.tech:8080/` → 200（实测全链路 ✓）。
**主分享链接 oh.sbbz.tech:8080 的手输/误贴从此自动升级，不再 400。**

## 各地址当前状态矩阵（实测）

| URL | 状态 | 说明 |
|---|---|---|
| `https://oh.sbbz.tech:8080/` | ✅ 200 | 主源 |
| `http://oh.sbbz.tech:8080/` | ✅ 301→https | 本次修复 |
| `https://play.sbbz.tech:2096/` | ✅ 200 | CF 加速源 |
| `http://play.sbbz.tech:2096/` | ❌ 400（**Cloudflare 边缘**） | 2096 是 CF 仅-HTTPS 代理端口，明文在边缘被拒，源站无法修 |
| `http://play.sbbz.tech:8080/` | ⚠️ CF 301 → `https://play.sbbz.tech/` → **404** | zone 的 Always-Use-HTTPS 摘掉端口后落到 443，而源站 443 是 bz 服务 |
| `https://play.sbbz.tech/`（无端口） | ❌ 404（bz 的响应） | 同上——**加 Origin Rule 前不要分享无端口链接** |

## 根治（用户面板操作，~3 分钟）

Cloudflare 控制台 → sbbz.tech → Rules → **Origin Rules** → Create：
`When: http.host equals "play.sbbz.tech"` → `Then: Destination Port → Rewrite to 8080`。
之后 `https://play.sbbz.tech/`（干净 URL，443）直达游戏，且：
- 无端口 → 浏览器/分享默认 https，400 类问题整族消失；
- `http://play.sbbz.tech:8080` 的 301 链也自然走通；
- `:2096` 可继续用或弃用均可。
（当前 API token 无 Rulesets 权限，故需面板一次性操作。）

## 沉淀

- nginx 明文误访 SSL 端口 → `error_page 497 =301` 是标准解，一处配置终身有效；
- CF 仅-HTTPS 代理端口（2053/2083/2086/2087/2096/8443）的明文访问**在边缘被拒**，
  源站任何配置都救不了——干净 URL（Origin Rule 到标准 443）才是终态。
