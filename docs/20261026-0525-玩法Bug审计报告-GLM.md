## 二、8 + 1 条报警的逐条判定（全部误报）

| 报警 | 判定 | 依据 |
|---|---|---|
| collage/rhythm/photo/temperature「有 scoreJump 无 thresholds」 | **误报** | 直跳型玩法的 tag 由玩法内自算（如 photo 按构图得分），scoreJump 直接按 tag 取节点，不需要 thresholds 判定表 |
| postcard `interpretations[].tag` 缺 | **误报** | postcard 用 `stamps` 字段做匹配键（双印记组合），非 tag；实现按 stamps 比对 |
| origami `min=3 > targets=2` | **误报** | `min` 是「至少折几步」，与 targets（答案表）无关；实现为 `Math.min(og.min \|\| 3, steps.length)` 有保护 |

## 三、审计中确认的**设计正确性**（容易被误判为 bug 的点）

1. **确认按钮初始 disabled**（26 个玩法）：未完成交互不可提交——正确设计；
2. **triage/wall/proofread 挂载时无浮层**：打字机前置（0.4s 后弹出），设计如此；
3. **快通提示条 300ms 自动收尾**：v3.4.13 有意设计（可点击保留）；
4. **hourglass/metronome 除零**：分母 total 为配置常量（有默认值），不会为 0。

## 四、审计结论与建议

**无需修复任何玩法。** 89 个玩法的工程质量在三个维度上都站得住：

- **清理纪律**：v2.9.0 的「引擎符号不可达」和 v3.4.9 的「minigame 挂 body」两次真实缺陷都被修掉后，
  现有玩法没有新的泄漏模式；`AbortSignal` 统一解绑的推广（senses/imagery 等）效果显著。
- **数据契约**：443 节点的玩法配置无悬空引用、无结构矛盾（另有 43 项测试 + 全图走查兜底）。
- **运行时**：53 个玩法实跑零错误。

### 唯一值得记录的风险（非 bug，属设计取舍）

**玩法超时/放弃路径缺失**：若玩家在某玩法内长时间不动（如 5 分钟），没有超时兜底或
「放弃」入口（timecapsule 有跳过按钮，其余 88 个没有明确放弃语义，只能靠快进模式）。
实际影响小（玩家可随时返回标题/读档），但**移动端误触后可能卡住**——已在建议中列为可选优化：
给 GameKit.createShell 加统一「暂离」按钮（保留进度关闭浮层，重进可继续）。
成本约半日，收益低（非阻断性），建议视试玩反馈决定。
