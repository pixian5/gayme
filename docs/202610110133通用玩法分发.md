# v2.8.5 · GameKit 通用玩法分发

> 时间：2026-10-11 01:33
> 版本：v2.8.4 → v2.8.5
> 目标：消除引擎里逐类型手写的玩法分发分支，让「玩法迁移」从「删分支 + 换调用」简化为「只删函数」。

## 一、问题

v2.7.9 起玩法分批迁往 `js/games/*.js`，但引擎侧每迁移一个玩法，都要在 `gotoNode` 里保留一个
`if (node.xxx) { setScene; renderCharacters; GameKit?.run("xxx", ...); ... }` 分支。
v2.8.4 后引擎里已有 26 个这样的分支（其中 23 个完全同构），每迁移一批就要多维护一批分支，
分发逻辑与玩法数量线性耦合。

## 二、改动

1. **`js/gamekit.js`**：新增 `types()`，按注册顺序返回已注册玩法类型清单，并加入导出对象。
2. **`js/engine.js`**：
   - `gotoNode` 在 triage / wall / proofread 三个特殊分支（带打字机前置）之后、「普通节点」之前，
     插入通用分发循环：
     ```js
     if (window.GameKit) {
       for (const type of window.GameKit.types()) {
         if (node[type]) {
           setScene(node.bg);
           renderCharacters(node);
           window.GameKit.run(type, node[type], nodeId);
           updateDayBar(node);
           updateHeartBar();
           return;
         }
       }
     }
     ```
   - 删除 23 个同构分支（breath / timecapsule / fold / reflection / lightdraw / mimic / season /
     pulse / palette / piano / origami / dye / weave / mirror / lantern / mosaic / stele / drum /
     jigsaw / chess / flag / postcard / timeline）。
   - **保留**三个特殊分支：triage / wall / proofread（需要先打字机再弹玩法，行为不同构）；
     **保留**全部未迁移玩法的分支（其类型不在注册表中，通用循环不会命中，行为不变）。
3. **`tests/interaction-coverage.test.mjs`**：gameKitHandlers 的逐字段引擎正则
   （`if (node.x)` + `GameKit?.run("x")`）替换为一条通用分发循环断言；`register("x")` 注册检查保留。
4. 版本号同步：`VERSION` / `package.json` / `index.html`（10 处 `?v=` + 标题页）/ `engine.js` 头注释。

## 三、行为等价性

- 分发优先级不变：特殊分支与未迁移玩法分支都在通用循环**之前**，命中顺序与原链一致；
- 已迁移玩法的分发路径由「手写分支」变为「通用循环」，两者执行的动作逐行相同
  （setScene → renderCharacters → run → updateDayBar → updateHeartBar → return）；
- 未注册类型不可能被通用循环触发，未迁移玩法行为零变化。

## 四、验证

- `npm test`：31 / 31 通过（含新的通用分发器契约断言）。
- `npm run test:syntax`：通过。
- engine.js：14,614 → 14,425 行（−189 行）。

## 五、收益

后续第 2~6 批玩法迁移中，每迁出一个玩法只需：删除 `run*` 函数 + 对应 `if (node.xxx)` 分支 →
新文件里 `register()`，**引擎分发不再需要任何改动**。
