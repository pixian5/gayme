## 二、仅剩的自主可做项（合计约一个工作单元）

### A1 · 全结局可达性测试（真实的测试盲区）★建议做

- **现状**：现有测试只断言「主线和真结局入口可达」「后日谈和明信片分支可达」；
  剧本内 **13 个 ending 声明**（三线各 3 + 学姐 SIDE + 未破环 + 破环 + 后日谈 + 真结局前章等）
  **没有全量可达性断言**。
- **风险**：「引用完整性」（测试有）≠「可达」（无断言）——若未来某个 bad ending
  的入口链被改断，现有测试不会红。
- **方案**：story-graph 补一条：对 `ENDINGS` 全部 id，从 START_NODE 做 BFS，
  断言每个结局节点可达（含经 choice/letter/scoreJump/moodJump 等边）。
  纯测试文件改动，~30 行。
- **验收**：13/13 可达（若有本来就不可达的——那本身就是发现）。

### A2 · Bold 字体懒加载（可选微优化，非 Mac 平台收益）

- 字体 688KB 中 **Bold 344KB 仅服务 3 处 CSS**（`font-weight: 700/bold`）。
- 非_traits Mac 平台（Mac 走本机 Songti SC 不下载）会为这 3 处多下 344KB。
- 方案：Bold 的 `@font-face` 保持，但**不 preload**、`font-display: swap`（现状如此）；
  可进一步把 3 处 700 字重改 600（子集只含 400/600 两字重？——子集重建涉及 WiFi 与源字体，
  收益/成本比低）。**建议：不动**，记录在案即可。itch 玩家首载核心 1.3MB 已达标。
