# v2.9.4 · 发布链路：GitHub Actions CI + GitHub Pages 自动部署

> 时间：2026-10-11 05:24
> 版本：v2.9.3 → v2.9.4
> 目标：补齐「无 CI、无 Pages 部署」的发布债务；版本号四处手工同步从此有 CI 兜底。

## 一、新增文件

| 文件 | 作用 |
|---|---|
| `.github/workflows/ci.yml` | push main / PR 时：Node 22 跑 `npm test` + `npm run test:syntax` |
| `.github/workflows/deploy-pages.yml` | push main：先跑同一套测试，通过后把**仓库根目录**（零构建站点）发布到 GitHub Pages |
| `.nojekyll` | 跳过 Jekyll 处理，静态文件原样服务 |

## 二、部署细节

- `actions/configure-pages@v5` 带 `enablement: true`：仓库尚未开启 Pages 时经 API 自动开启，
  无需手动到仓库设置里点。
- `concurrency: pages` 组取消进行中的旧部署，避免竞态。
- 部署地址：`https://pixian5.github.io/gayme/`（首次推送后生效）。
- 注意：仓库同时有 gitee（origin）与 github 两个远程；Pages 部署只由 GitHub 的 workflow 触发，
  gitee 侧如需页面服务可后续单独配置。

## 三、验证

- `npm test` 31 / 31 通过；workflow YAML 经本地 `python3 -c "import yaml"` 校验语法（见提交前检查）。
- 首次真实部署在推送到 GitHub 后由 workflow 执行，结果在仓库 Actions 页可查。
