## 二、修复：cg_festival 无解锁点（内容缺口）

- **问题**：CG「学园祭之夜」定义完整（灯笼/祭典 SVG），但全 SCRIPT 没有任何节点
  `cg_unlock: "cg_festival"`——玩家永远无法解锁这张 CG，图鉴收集率永远差 1/11
- **修复**：接入后日谈开篇 `afterword_entry`（day 14 night bg=festival，真结局后人人可达，
  场景契合祭典回顾）`cg_unlock: "cg_festival"`
- **影响面**：真结局通关玩家进入后日谈即解锁；无剧情副作用

## 三、新增契约测试（防再犯）

1. **每张 CG 至少有一个解锁点**：CGS 中每张 CG 必须有 ≥1 个 `cg_unlock` 引用
2. **requires_memory 引用必须存在**：静态 memory 对象 id ∪ 字符串 memory（perspective/回信）
   必须覆盖全部 requires_memory

静态测试 36→**38** 项。

## 五、经验

1. **"写了但没接"是数据类常见缺口**：CG/结局/记忆等收集项定义完整 ≠ 已接入剧情。
   必须用"每项至少一个解锁点/引用点"的契约测试兜底，否则玩家永远拿不到而开发无感。
2. **审计口径要先校准再下结论**：requires_memory 初次审计报"断链"，实为脚本只收集了
   静态 memory 对象、漏掉 perspective 动态记忆——修正口径（138 源）后全部有效。
   审计脚本本身要覆盖数据的所有来源形态。
3. **性能验证要带正确的请求头**：curl 不带 Accept-Encoding 时 nginx 不返回 gzip，
   "没开 gzip"是测试方法错误；配置里早已开启。
