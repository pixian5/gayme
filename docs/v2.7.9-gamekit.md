# v2.7.9 玩法框架基座（GameKit）与后日谈玩法迁移

## 本轮目标

建立统一玩法外壳，把重复的「创建浮层 → 交互 → 判定 → 结果面板 → 跳转收尾」收敛到一处，
并将后日谈 5 个玩法从 engine.js 外迁，验证渐进式重构路线可行（不改行为，只改组织方式）。

## 新增文件

| 文件 | 作用 |
|---|---|
| `js/gamekit.js` | 玩法框架基座：注册表、浮层外壳、结果收尾、进度文案、宿主桥 |
| `js/games/afterword.js` | 后日谈 5 个玩法的实现（明信片 / 时间线 / 分拣 / 留言墙 / 校对） |

## 统一能力（GameKit）

- `register(type, handler)` / `run(type, config, nodeId)`：玩法注册与触发表
- `createShell({ kind, nodeId })`：统一创建浮层（`xxx-layer`）、隐藏对话框、**注册 GameLifecycle**（读档 / 返回标题时安全销毁）
- `shell.finish(result)`：统一收尾 —— 写入记录 → 应用数值/性格 → 展示结果面板 → 关闭并跳转
- `formatProgress(count, total, verb)`：统一进度文案
- `attachHost({ gotoNode, applyAdd, updateHeartBar, escapeHtml })`：由 engine.js 启动时注入宿主能力

engine.js 的分发点相应改为 `window.GameKit?.run("postcard", node.postcard, nodeId)` 等形式。

## 迁移范围

| 玩法 | 节点 | 结构 |
|---|---|---|
| 明信片印记 | `afterword_postcard` | 单列多选（选 2 枚印记） |
| 时间线排序 | `afterword_timeline` | 顺序排列 |
| 回信分拣 | `afterword_mailbox_triage` | 双列匹配（一对一） |
| 留言墙 | `afterword_wall` | 双列匹配（多对一） |
| 校刊校对 | `afterword_proofread` | 双列匹配（多对一） |

三个双列匹配玩法共用 `runMatchGame(spec)` 工厂，文案与判定差异经配置项传入。

## 浏览器回归中发现的回归与修复

- **问题**：抽象 `runMatchGame` 时，把「分拣」的一对一清空语义（一个回应只能对应一封信）
  误用到「留言墙 / 校对」上，导致多张留言放入同一位置时互相清除（进度停在 3/4）。
- **修复**：新增 `spec.exclusiveBin` 配置项 —— `triage` 启用，`wall` / `proofread` 不启用。
- **教训**：同构玩法的差异点（一对一 vs 多对一）必须在抽象时显式建模，不能只对齐 UI 结构。
