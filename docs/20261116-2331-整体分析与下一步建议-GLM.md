## 二、架构风险与新事实（本轮分析核心增量）

### 1. 域名与部署拓扑现在互相矛盾 ⚠️（需要重新决策）

oh/play 的 CNAME 指向 **HF Space——而 HF 已停更冻结在 v3.4.43**。这意味着：
**现在去加 Origin Rule，域名复活的也是旧版**（v3.4.43 之后永远不再更新）。
域名要服务活版本只剩三条路：

| 方案 | 做法 | 成本 | 评价 |
|---|---|---|---|
| A. 域名保持死亡 | 什么都不做 | 0 | 现状；只有一个 instabox.tech 长链接可用 |
| B. 域名指向冻结 HF | 加 Origin Rule | 2 分钟 | 域名复活但**永远是 v3.4.43**，和盒子版本漂移，不建议 |
| C. **Cloudflare Tunnel 接盒子**（推荐如果要域名） | 盒子上已有 cloudflared 二进制（免流项目装过）；起一个 tunnel → 本机 8090，CF 侧把 oh/play CNAME 改到 tunnel 域名 | 约 1 小时 + 面板确认 | 域名直连**活**盒子版本；HTTPS 由 CF 边缘终结，绕开「盒子无公网入站」的根本限制 |

### 2. 单点可用性观察（不紧急，记录在案）

盒子是唯一线上入口。实测连跑 7 天未暂停（autoSuspend 未设），但元数据里 maxRun=360
含义不明、且你 11-16 早些时候报过一次「服务器挂了」（疑似一次暂停后被 exec 唤醒）。
**低成本保险**（可选）：GitHub Actions 加一条定时 workflow（每小时 curl 盒子 8090，
失败时用 InstaBox API key 唤醒 + bark 通知你）。半小时搭好，把单点从「静默挂」变「挂了有人知道」。

### 3. CI 目前只跑契约

e2e 六套仍只在盒子/本地手动跑。CI 扩 e2e（chromium）可让并行线在 PR 阶段就被全量回归
拦住——上次并行线合并时我们并不知道对方改了什么，现在有 CI 了但网还不够密。
