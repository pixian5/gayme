# v2.8.3 工程瘦身与自托管字体

> 记录时间：2026-09-30 02:02
> 版本：v2.8.2 → v2.8.3
> 类型：技术债修复（结构瘦身 + 表现升级），无剧情改动

## 一、背景

本轮处理两条长期挂账的技术债：

1. `js/saves.js` 的 106 个 localStorage 键各自手写「读取 / 写入 / 读单条」三件套，形态完全一致却重复上千行；`clearAll()` 还复制了一份与 `GAME_STORAGE_KEYS` 等长的 106 项键清单。
2. `css/style.css` 声明了 `"Noto Serif SC"`，但项目从未加载该字体（无 `@font-face`、无 CDN 链接），实际一直静默回退到 `Songti SC` / `STSong`；`index.html` 里还残留一条无用的 `fonts.googleapis.com` preconnect。

## 二、saves.js 工厂化

### 方案

在 `const Saves = {` 之前新增两个工厂，只统一实现，不动公共 API：

- `recordStore(key, name, fields, names?)`
  生成 `getXxxRecords()` / `saveXxxRecord(nodeId, ...)` / `getXxxRecord(nodeId)`，存储结构固定为 `{ [nodeId]: { ...fields, ts } }`。
  - `fields` 支持 `"字段名"`（取自入参）与 `["字段名", 字面量]`（固定默认值，如时光胶囊的 `delivered: false`）。
  - `names` 用于覆盖方法名，兼容命名不规则的存储（Letter / Doodle / Collage / Photo / Rhythm 的列表方法名带 `s`，单条方法名不带 `Records`）。
- `unlockListStore(key, listName, addName, hasName)`
  生成「解锁型 id 列表」三件套：已存在返回 `false`，新增才写入（关键词 / CG / 环境线索）。

### 落地范围

| 类别 | 数量 | 说明 |
|---|---|---|
| `recordStore` 常规命名 | 82 组 | 各玩法记录（占卜 / 茶席 / 星象 / 后日谈时间线分拣等） |
| `recordStore` 覆盖命名 | 5 组 | Letter、Doodle、Collage、Photo、Rhythm |
| `unlockListStore` | 3 组 | 关键词、CG 图鉴、环境线索 |
| `clearAll` 去重 | 1 处 | 改为 `[META_KEY, ...GAME_STORAGE_KEYS]`，消除 106 项重复清单 |

未纳入工厂的是确有个性化逻辑的部分：存档槽位（`save/load/deleteSave`）、设置（归一化与范围校验）、导入导出回滚、`setFlag/getFlag`（带默认值参数）、收件箱（多字段局部更新 + 回滚）、朋友圈点赞（三态返回）、气味收集（`collected/recalled` 双层结构）、记忆碎片 / 梦境碎片 / 回声台词（自定义记录体）。这些保持原样，改动越少越安全。

### 结果

- `js/saves.js`：**1918 行 → 1208 行（-710 行，-37%）**
- 公共 API 方法名、参数、返回值、localStorage 键名 **全部零变化**，`engine.js` 等 412 处调用点无需改动

### 验证

除常规测试外，本轮额外做了一次「新旧实现对拍」：

- 把改动前的副本与改动后的实现分别放进带假 `localStorage` 的 `vm` 沙箱，冻结 `Date.now()`；
- 从旧文件静态解析出 341 个方法名与入参个数，按声明顺序逐一对两者发起 683 次调用（两轮，第二轮读取第一轮写入的数据）；
- 比对 `Saves` 键集合、每个键的类型、每次调用的返回值、最终 106 个存储键的完整内容。

结果：**全部一致**。`clearAll` 单独验证（先写入一批记录再清空，比对清空前后键数与返回值），同样一致。

## 三、自托管 Noto Serif SC 子集

### 方案

不引入 CDN（保持零运行时外部依赖、离线可用），改为随仓库分发自托管子集：

1. 下载官方 `NotoSerifSC-Regular.otf`（11.6MB）与 `NotoSerifSC-Bold.otf`（11.7MB）；
2. 用 `pyftsubset` 按「项目里真正出现的字符」裁剪：扫描 `index.html` + `css/*.css` + `js/**/*.js` 得到 1625 个字符，再补齐 ASCII 可打印字符与常用中文标点/全角符号，共 **1713 个字符（其中汉字 1444 个）**；
3. 产出 `fonts/NotoSerifSC-Regular.woff2`（316KB）与 `fonts/NotoSerifSC-Bold.woff2`（329KB），**合计 660KB**；
4. `css/style.css` 顶部新增两条 `@font-face`（400 / 700，`font-display: swap`）；
5. `index.html` 把无用的 `fonts.googleapis.com` preconnect 换成两条字体 `preload`（`as="font" crossorigin`），并移除了该残留链接。

### 重新生成子集的命令

新增文案后如果出现子集未覆盖的汉字，按以下步骤重建（命令与本次一致）：

```bash
# 1) 准备工具（项目根目录）
python3 -m venv .venv
.venv/bin/pip install "fonttools[woff]" brotli

# 2) 生成字符集（index.html + css + js 全部字符，另补 ASCII 与常用中文标点）
#    具体见本文件上一节描述；输出到 /tmp/font_charset.txt

# 3) 裁剪为 woff2（两个字重各执行一次）
.venv/bin/pyftsubset <字体源文件>.otf \
  --text-file=/tmp/font_charset.txt \
  --flavor=woff2 --layout-features=* --no-hinting --desubroutinize \
  --output-file=fonts/NotoSerifSC-<Regular|Bold>.woff2
```

### 注意事项

- 子集有 40 个字符未覆盖，全部是 emoji / 符号（📩 🌸 🏠 🔍 等 UI 图标），由系统 emoji 字体回退，不影响中文与排版。
- `@font-face` 的 `src` 与 `index.html` 的 `preload` 必须使用**完全相同的 URL**（当前都带 `fonts/` 前缀、不带查询参数），否则浏览器会重复下载。本次已验证两个 woff2 各只请求一次。
- 字体文件未加 `?v=` 版本参数：它由 CSS 引用、内容极少变动，避免为此增加又一个版本同步点。若重新生成子集后需要强刷用户缓存，可改文件名。
- 字体回退链保持 `"Noto Serif SC", "Songti SC", "STSong", "PingFang SC", serif`，即使字体加载失败也不会出现乱码或空白。

### 验证

浏览器（headless chromium）实测：

- `document.fonts.check('16px "Noto Serif SC"')` → `true`；`document.fonts.load('700 32px …')` 后两个字重均 `loaded`
- `body` / `.title-cn` 的计算 `font-family` 首选即为 `"Noto Serif SC"`
- 两个 woff2 均 200，且**各只有 1 条 resource 记录**（preload 与 `@font-face` 未产生重复下载）
- 标题页渲染正常，版本号显示 `v2.8.3 · Demo`，控制台无脚本报错

## 五、遗留与建议

1. **玩法同质化**：对齐 / 拼图 / 调色类机制重叠仍在，属于内容问题，建议发布后按玩家反馈处理。

3. **子集字符集是快照**：它对应 v2.8.3 的文案。剧情继续扩张后要重新生成，否则新字会回退到系统宋体（不会报错，只是字形不统一）。建议在每次大版本发布前跑一次重建。
