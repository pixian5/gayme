## 三、流量实测的三个数字（对玩家有意义）

1. **首次进站 2.83MB**：核心 precache（html/css/js/字体/图标）。BGM 是运行时缓存且默认
   不自动播放，静音玩家整局都不下载音频——比 README 里"首装 11MB"的旧数据好得多
   （v3.3.19 三层缓存改造的成果）。
2. **回访 0 出网**：46/46 响应来自 SW 缓存。老玩家回来刷新页面几乎不耗流量。
3. **全剧本通关总流量 ≈ 3MB 量级**：对手机流量玩家友好。

## 六、操作记录（复现用）

```bash
npx playwright install chromium        # 本机内核缓存被清过，重装（99MB，有线宽带）
node .playtest-hf.mjs careful          # 首跑：全新 profile，走真实网络
node .playtest-hf.mjs lazy             # 二跑：46/46 命中 SW 缓存
node .playtest-hf.mjs explore          # 三跑：同上
```

脚本要点（与本地版 `.playtest.mjs` 的差异）：
- `chromium.launchPersistentContext("/tmp/hf-playtest-profile")`——跨进程共享 SW 缓存；
- 不传 `serviceWorkers: "block"`——真实玩家带 SW；
- 每个画像开始前 `localStorage.clear()`（当新玩家），但保留 CacheStorage（资源缓存）；
- `page.on("response")` 统计 content-length 与 `fromServiceWorker()` 命中数、收集 ≥400 响应。
