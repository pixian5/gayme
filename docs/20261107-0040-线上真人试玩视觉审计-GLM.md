# 线上真人试玩·视觉审计（GLM）

> 2026-11-07 00:40 · 模型：GLM · 被测：HF Space v3.4.35（真实环境，1280×800）
> 方式：浏览器实际游玩 + 逐屏截图（标题/引导/序章/立绘/星座/涂鸦/设置），非 DOM 模拟。
> 前几轮试玩全部只读 DOM 文本，视觉层（布局/配色/残影/可读性）首次被审计。

## 一、发现的问题（按优先级）

### P1 · 首屏无样式闪烁（FOUC）
首次打开 2.5 秒以上页面处于"裸奔"状态：菜单按钮竖条化、游戏大标题消失、背景只剩渐变
（已截图存档）。CSS 完整加载后一切正常。HF 冷缓存/慢网络下裸奔窗口更长，第一印象损伤大。
**建议**：在 index.html `<head>` 内联标题页关键样式（约 40 行：title-main/title-menu/button），
或加一个纯 CSS 的加载遮罩。半天工作量。

### P2 · 旁白时说话人名牌空置残留
speaker 为空的旁白节点，名牌位置残留一个孤立小灰条（序章多张截图可见）。
**建议**：speaker 为空时隐藏名牌元素（1 行）。

### P3 · 场景切换瞬间背景残影（观察项）
cherry→classroom 切换的过渡帧出现上新粉下黄混合（0.x 秒）。几乎无感，记录备查。

### P4 · 自动化不可点击标题菜单（测试侧注意项）
标题按钮带常驻浮动动画，Playwright「元素静止」检查永远超时；真人点击无碍。
graph.e2e 用 evaluate 点击所以从未暴露。以后写 UI 自动化用坐标点击（cua）或 evaluate。

### P5 · 玩法遮罩 backdrop-blur 把下层 UI 模糊成光斑（观察项）
涂鸦玩法浮层背后，对话框文字与心条面板被 blur 成大光斑，乍看像"乱码残影"。
确认为设计行为（非 bug）；若觉得干扰，可在玩法浮层打开时隐藏对话框。
