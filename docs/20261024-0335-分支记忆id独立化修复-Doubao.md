# v3.3.2 分支记忆 id 独立化修复（Doubao）

日期：2026-10-24 03:35 · 模型：Doubao · 版本：v3.3.2

## 背景

用户要求"自行分析进度并全部优化"。本轮对剧情数据做**记忆系统全面审计**，
发现 7 组分支互斥记忆共用 id 的内容 bug 并修复。

## 一、问题定位

`Saves.saveMemory(id, text)` 按 **id 去重**（`!list.find(m => m.id === memoryId)`）。
SCRIPT 中 7 组（15 处）**分支互斥记忆**写成了同一个 id，导致：

- 玩家走第一个分支时保存该分支的记忆文本
- 二周目走另一分支时，`isMemoryUnlocked(id)` 已返回 true → **新分支的记忆永远无法保存**
- 图鉴里只显示最早解锁的那条，其余分支记忆（有效的剧情文本）永久缺失

## 二、修复清单（15 处拆分独立 id）

| 原 id | 分支 | 新 id |
|---|---|---|
| 诗雨·开场 | 鼓励 / 冷静 | 诗雨·开场·鼓励 / 诗雨·开场·安静 |
| 回声·敢 | 承认 / 否认 / 沉默 | 回声·敢·承认 / 回声·敢·否认 / 回声·敢·沉默 |
| 诗雨·题记 | 丰沛 / 省略 | 诗雨·题记·丰沛 / 诗雨·题记·省略 |
| 夏织·同步 | 跟上 / 乱了 | 夏织·同步·跟上 / 夏织·同步·乱了 |
| 苏念·海报 | 取景 / 未取 | 苏念·海报·取景 / 苏念·海报·未取 |
| 沉默·回信 | 承认不知道 / 沉默 | 沉默·回信·承认 / 沉默·回信·沉默 |
| 苏念·一笔 | 用力 / 安静 | 苏念·一笔·用力 / 苏念·一笔·安静 |

- 影响面：requires_memory 仅 2 处（序章·诗雨）不涉及这些 id；无其它代码引用旧 id（已递归检查干净）
- 存档兼容：旧存档里已保存的旧 id 记忆仍在（不影响展示）；新分支走通后正确入档
- 意义：分支选择的记忆二周目可补齐，图鉴收集率统计（v3.3.1）的数字将真实反映收集进度

## 三、契约测试（防再犯）

consistency 新增「SCRIPT 内 memory id 全局唯一」测试：
`memory: {...id: "..."}` 全量提取 → 断言无重复。静态测试 35→**36** 项。

## 四、验证

- 审计脚本：唯一 memory id 125 个 / 重复 0（修复前 117 唯一 / 7 重复）
- 语法：script.js / engine.js node --check 通过
- 静态：36/36
- e2e：7/7
- 学姐线抽查：24 节点时间线单调无回退、speaker 仅「学姐/沈屿」、文本连贯且符合形态 A 设定（不救人不召回，只陪伴）
- 线上：push 后服务器 cron 自动部署 → v3.3.2

## 五、经验

1. **记忆/图鉴类数据要定期做 id 唯一性审计**：saveMemory 静默去重是"看不见的 bug"——
   不报错、不崩溃，只是图鉴悄悄缺内容。此类问题必须靠自动化审计 + 契约测试兜底。
2. **分支互斥记忆必须独立 id**：同一条剧情选择的两个分支文本，若共用一个 id，
   后走的分支永远写不进去；独立 id 才能让二周目补齐成为可能。
3. **契约测试是数据类 bug 的防线**：memory 格式（字符串 id）、id 唯一性、节点引用——
   这类静态契约成本极低、收益极高。
