## 一、核心发现：重玩路径堵在玩法层（P0）★★★★★

### 事实链（全部代码实测）

1. 本游戏的**目标玩法形态就是多周目**：二周目解锁回望与学姐线入口、三周目解锁真结局破环；
2. 第 5 日回溯后，`d4_dice → … → d15_rewind → d5_loop_arrival` 玩法链
   （第 6~15 日，**30+ 个玩法节点**）**每一轮必经**——这是通往路线选择/学姐线的唯一路径；
3. 但「跳过已读」（v3.3.6 快进）**明确不覆盖互动节点**——engine.js 注释原文：
   「遇到未读节点或选项/信件/小游戏等互动节点会自动停下」；
4. 89 个 GameKit 玩法里**只有 1 个**（timecapsule）有跳过按钮，其余 88 个必须手动完成交互。

### 推论

想打三周目的玩家，在第 2、3 轮仍要**手动重玩 30+ 个玩法**才能到达路线选择——
单轮重玩 ~40 分钟，其中绝大部分是机械重复。这不是工程 bug，是**循环游戏的核心体验缺口**：
我们写了 162 个节点的多周目文本（loopText）来奖励重玩，却没解决「重玩本身很累」。
**玩家根本走不到那些文本，或者走到了但已经烦躁。**

### 方案：已读快通（GameKit 统一层实现）

- 触发条件：`state.skipMode === true`（快进中）且当前节点 `visitedNodes > 1`（已读）；
- 实现（一处改动，88 个玩法自动受益）：`GameKit.createShell` 在挂载时检测上述条件 →
  在浮层顶部显示「⟲ 已读 · 点击快通」按钮，且**快进模式下 200ms 后自动完成**；
  收尾走现成的 `shell.finish({ tag: "revisit", label: "——重访", next: node.next })`
  ——中性结果、不写 record、不加成，直接跳转（复用完整收尾链，生命周期安全）；
- 3 个基础 minigame（writing/running/painting）在 runMinigame 同样处理（按 50 分中性完成）；
- choice / letter / echo **保持必停**（关键决策不该被快进吞掉）；
- engine 需把 `skipMode`/`visitedNodes` 经 host 桥暴露给 GameKit（一行）。

**预期收益**：二周目单轮 ~40 分钟 → ~10 分钟（只在真正的决策点停）。
这是「让 162 个 loopText 被看到」的前置条件，也是多周目留存的关键。

## 二、修正上轮判断：d 链 loopText 值得做轻量层（P1）

上一轮我说「d 链 prompt 类 loopText 不做」，理由是「玩法 prompt 短、重复感弱」。
**这个判断错了**，错在忽略了一个事实：d 链每轮必经，是全游戏**重读率最高**的文本。
快通落地后，玩家会高频掠过这些节点——变体文案的价值反而上升。

- 范围收窄：只做 **~15 个锚点**（d6/d9/d12 章节开头已有呼吸点，补关键道具节点与
  d5_rewind / d15_rewind / d5_loop_arrival 等循环仪式节点），2 段式（原文 + 一句既视感）；
- 不做 195 个全量——快通场景下玩家本就快速掠过，锚点足够建立「这一轮我又来了」的氛围。

## 六、一句话总结

前两轮从工程侧看项目「已经开发完了」是对的；但换个玩家视角看，**循环游戏的重玩通道还堵着**——
88 个玩法在二周目无法跳过、30 个玩法节点每轮必经。快通功能（~60 行）是让这个游戏
「配得上自己精心写的多周目内容」的最后一块拼图，也是 itch 发布前最值得做的事。
