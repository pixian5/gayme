## 二、操作过程

1. **验证令牌与连通性**（先做，避免盲推）：

   ```bash
   curl -sS -o /dev/null -w "%{http_code}\n" https://api.github.com/user \
     -H "Authorization: Bearer <TOKEN>" -H "User-Agent: gayme-deploy"   # → 200
   curl -sS https://api.github.com/repos/pixian5/gayme                   # → private:false（公开仓库）
   ```

   结论：令牌有效、仓库已存在且为**公开**、默认分支 `main`。

2. **写入凭据到远程**：`git remote set-url github https://<TOKEN>@github.com/pixian5/gayme.git`
   （令牌只落本地 `.git/config`，不会进版本库；但仓库公开，源码本身对外可见）。

3. **首次 push 失败**：

   ```
   fatal: unable to access 'https://github.com/pixian5/gayme.git/':
   GnuTLS recv error (-110): The TLS connection was non-properly terminated.
   ```

   `curl` 能连通（HTTP/2 → 200），但 git 走 GnuTLS 上传约 17MB pack 时被中断。
   单独改 `http.version=HTTP/1.1` 无效；加了 `http.postBuffer=524288000` 后成功：

   ```
   To https://github.com/pixian5/gayme.git
      4e899f5..c0e35e8  main -> main
   ```

4. **结果校验**（三远程同一 SHA）：

   | 远程 | 地址 | refs/heads/main |
   |---|---|---|
   | `origin` | gitee.com/ibjxk/gayme（部署主源） | `c0e35e8` |
   | `gitcode` | gitcode.com/laotongtian/gayme | `c0e35e8` |
   | `github` | github.com/pixian5/gayme（公开备份） | `c0e35e8` |

   GitHub 上另有 `gh-pages` 分支（`caf0033`，只放跳转页），本次未动、保留完好。

## 五、经验要点（可直接复用）

- **curl 通 ≠ git 能推**：判定远端可达性要用 `git ls-remote`（注意别用 `| head` 吞掉退出码，
  本次就是被管道掩盖成「空远端」，误以为 GitHub 是空仓库）。
- **GnuTLS recv error (-110)** 多见于大 pack 上传中断：`http.postBuffer` 放大到 500MB 首试，
  再配合 `http.version=HTTP/1.1`；不要因为 curl 能连就怀疑令牌或网络策略。
- **强推的代价**在服务器 cron 场景要等一轮 cron 才看得出来；补救方法是让新历史成为旧提交的
  后代（基于旧提交 merge 新主线），而不是再次强推。
- **公开仓库**意味着源码与素材对外可见；令牌写入 remote URL 只影响本地 `.git/config`，
  但换机器克隆时应改用干净的 `https://github.com/pixian5/gayme.git` 地址。
