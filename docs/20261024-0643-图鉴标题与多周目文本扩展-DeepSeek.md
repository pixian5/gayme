## 一、图鉴记忆标题补全

`inbox` / 自由回信 / 视角三处的记忆 id 是**字符串**写法，`saveMemory` 只传了 id 与正文，
没有 title → 图鉴卡片显示 id（如 `诗雨·敢`），不如对象记忆（有 `title`）友好。

修复：

| 位置 | 改动 |
|---|---|
| script.js | 15 处字符串 memory 各补 `memoryTitle`（inbox 6 + 回信 8 + 视角 1） |
| engine.js | inbox / 自由回信 / 视角三处 `saveMemory` 调用补传 `memoryTitle` |

标题示例：`回信·推开门`、`回信·写下去`、`写给学姐·勇敢`、`回信·致学姐`、`走廊的另一面`。
旧存档已写入的旧记忆无 title，仍回退 id（不迁移、不回填）。

## 二、多周目文本扩展（loopText）

loopText 覆盖由 **40 → 45 节点**，补齐几处高信号节点（此前只有初周原句）：

- `d4_night_family` / `d4_night_family_2`（家庭线「未寄的话」）
- `d10_senior_slip` / `d10_senior_slip_2`（学姐中段线索「咽回去的半句」）
- `afterword_entry`（真结局后日谈开篇）

每处补足三段（初周 + 二周目既视感 + 三周目更深），遵循既有约束：不剧透、不解释循环机制、
随 `loopCount` 单调加深；引擎按 `idx = min(loopCount, len-1)` 取文本。

## 三、契约测试（41 → 42 项）

1. **每个字符串 memory 都配有 memoryTitle**：`memory: "X"`（排除 `requires_memory`）数量
   必须等于 `memoryTitle` 数量，且标题不重复——防止将来新增字符串记忆忘配标题。
2. **loopText 数组结构规范**：每个 loopText 至少 2 段、引号成对，避免段数不足退化成永远原句。

## 五、经验

1. **两条写入路径都要带全字段**：记忆有「对象」与「字符串」两种写法，对象写法天然带 title，
   字符串写法容易被漏掉 title → 图鉴退化成显示 id。凡是成对的写入路径，字段要补齐。
2. **契约要能卡住「成对关系」**：字符串 memory 与 memoryTitle 是 1:1，用「数量相等 + 不重复」
   做契约，就能在下次漏配时立刻报警，比逐条人工检查可靠。
3. **多周目文本是「加深」不是「反转」**：二/三周目变体只让同一件事看得更清楚（既视感 +
   更深的理解），不揭示循环真相、不改剧情走向，才能既保鲜又不剧透。
